# Ввод и вывод C внутри пространства

Профиль ввода-вывода включается при генерации образа флагом `--io`.
В базовом профиле ECALL по-прежнему вызывает исключение. Профиль не
предоставляет ОС; поддерживает ровно три операции через существующие IN/OUT.
Все проверки аргументов, выбор операции и возврат результата выполняются
копированиями. Ядро эмулятора пространства не разбирает ECALL.

| a7 | Операция | Аргументы | Результат в a0 |
| --- | --- | --- | --- |
| 63 | чтение | a0=0, a1=гостевой адрес буфера, a2=число байтов | число прочитанных байтов; 0 при EOF |
| 64 | запись | a0=1, a1=гостевой адрес буфера, a2=число байтов | число записанных байтов |
| 93 | завершение | a0=код завершения | остановка, код сохранён в пространстве |

Чтение использует IN, запись — OUT. После чтения или записи pc увеличивается
на 4, остальные регистры сохраняются. Неподдерживаемая операция возвращает
-38; неверное значение a0 для чтения/записи — -9; недопустимый диапазон
буфера — -14; ошибка канала без переданных байтов — -5. Отрицательные
значения представлены 32-битным дополнительным кодом. Отдельного errno нет.
Если передано несколько байтов до ошибки, возвращается их число.
Неполное чтение при EOF тоже возвращает число переданных байтов.

При нулевой длине корректная операция возвращает 0 без обращения к каналу
и без проверки указателя. Ненулевая операция требует, чтобы весь буфер
лежал в выбранной гостевой памяти (по умолчанию 0..524287). Переполнение суммы адреса и длины
не позволяет обращаться к служебным данным пространства. Доступ к байтам
не требует выравнивания. Чтение наследует поведение текущего IN: ожидает
запрошенное число байтов, EOF или ошибку; это не обещание семантики Linux read.

Завершение устанавливает причину остановки 10; pc остаётся на ECALL.
32-битный код сохраняется по адресу STATUS+32. PROCESSOR очищается самим
образом. EBREAK и ошибки машинных инструкций сохраняют прежние причины.
Контрольные кадры несовместимы с этим профилем: OUT содержит только данные
гостевой программы. Наблюдение доступно через существующий журнал копирований
и конечный дамп пространства, отдельно от OUT.

Минимальная поддержка C предоставляет `cs_read`, `cs_write`, `cs_exit`,
запуск `main(void)` и возврат его результата в cs_exit. Компиляция нацелена
на RV32I/ILP32 без ОС; подключаются операции памяти и доступная библиотека
компилятора libgcc для программных умножения и деления. Это не полная libc.

Общая команда сборки принимает один или несколько C-файлов и создаёт
сырой машинный код, ELF, образ пространства и описание размещения.
Обычный `space` получает общие параметры `--dump-space` и `--trace` для
сохранения конечного состояния и наблюдения за копированиями. Эти функции
находятся вне ядра и не зависят от RV32I; формат журнала общий с проверочной
программой. Команда запуска передаёт stdin/stdout в IN/OUT и читает из конечного
дампа только причину остановки и код завершения. На хосте не исполняются
арифметика RV32I или обработчики ECALL. Код процесса равен младшим восьми
битам кода гостя при причине 10; ошибка исполнения или внешний предел — 125.

Проверка пути: C-программа читает два беззнаковых 32-битных числа,
складывает их по модулю 2^32 и выдаёт сумму; проверяются нормальное чтение,
переполнение, неполный ввод, EOF и ошибки обоих каналов. Дополнительно
проверяются нулевая длина, неизвестная операция, неверный номер потока,
края памяти и недопустимые диапазоны. Образы, IN/OUT, дампы и сырые журналы
сохраняются как артефакты тестов.

## Сборка и запуск

Чтобы загрузить RV32I и программу через стандартный IN без `--core`,
используй `build.py --stream` и `run.py --stream`.
Пример и проверки описаны в [загрузке RV32I](rv32i_loading.md).

```sh
make
python3 scripts/rv32i/build.py examples/rv32i/sum.c -o tmp/sum.bin
printf '1 2\n' | python3 scripts/rv32i/run.py tmp/sum.bin
```

Вывод: `3` и перевод строки, код процесса 0. Пример читает десятичные
беззнаковые числа 0..4294967295, разделённые пробельными символами;
сложение выполняется по модулю 2^32. Неполный или неверный ввод даёт код 2,
ошибка IN — 1, неполная запись или ошибка OUT — 3. Ввод читается по одному
байту, поэтому программа не требует EOF после разделителя второго числа.

`build.py` принимает несколько исходных файлов. `--optimization O0` выбирает
режим без оптимизации, по умолчанию O2. `--stack` задаёт начальный x2,
выровненный на 16 байт; при размещении оставляется не менее 1024 байт под
стек. Заголовок `copy_space.h` автоматически доступен исходным файлам.
`--memory-bytes` выбирает 65536, 131072, 262144 или 524288 байт;
по умолчанию 524288. Без `--stack` начальный x2 равен размеру памяти
минус 16. Верхняя граница проверяется и при сборке C, и внутри пространства.
Компилятор ищется так же, как в проверке RV32I; `--compiler` или RISCV_CC
задают его явно. Нужна библиотека libgcc для RV32I/ILP32.
С `-nostdlib` функции памяти и libgcc предоставляются явно, как описано
в [документации GCC](https://gcc.gnu.org/onlinedocs/gcc/Link-Options.html).

Рядом с `tmp/sum.bin` создаётся `tmp/sum.bin.json`, содержащий размещение
и исходные файлы. Каталог `tmp/sum.bin.build` содержит ELF, машинную
программу, команды компиляции, сообщения компилятора, карту размещения
и дизассемблирование. Генератор подготавливает только исходный образ;
при запуске C выполняется исключительно инструкциями пространства.

Можно запустить образ напрямую: `build/bin/space --core tmp/sum.bin`.
OUT содержит тот же текст; код процесса обычного space отражает ошибку
эмулятора, а код гостевой программы сохраняется в пространстве.
`run.py` дополнительно возвращает код гостя процессу хоста, читая два поля
из конечного дампа. Он не зависит от тестовой программы запуска.

`run.py --in FILE --out FILE` перенаправляет файловые дескрипторы в IN/OUT;
без этих параметров наследуются stdin/stdout. `--trace FILE` и
`--dump-space FILE` сохраняют диагностику отдельно от OUT; `--ticks N`
задаёт внешний предел. Без `--dump-space` используется временный дамп,
который удаляется после чтения кода завершения.

## Проверки

`make test` включает 24 программы с независимым сравнением регистров,
конечной памяти, кодов возврата и событий каналов. Дополнительно два
потока с fopencookie сначала передают 3 байта, затем возвращают ошибку:
реальные fread/fwrite дают ненулевой результат вместе с ferror; образ
возвращает 3, а не -5. Проверены файлы диагностики обычного space,
повторные операции, нулевая длина, полный диапазон 64 КиБ, края памяти,
неизвестные операции и недопустимые аргументы. Базовые тесты RV32I
сохраняют прежний профиль с исключением ECALL.
Дополнительно проверяются 36 выполнений с выбранными объёмами памяти:
большие адреса, верхняя граница, переполнения, ввод/вывод на всех 512 КиБ
и загрузка программы с entry на последней инструкции памяти.

`make test-rv32i-c` включает сквозные проверки скомпилированного C:
десятичное сложение, переполнение, EOF, неверный и неполный ввод,
короткое чтение буфера, ошибки IN/OUT, возврат кода завершения 300 как
кода процесса 44, сборка нескольких файлов при O0/O2 и операции памяти
с перекрытием. Проверяются также внешний предел и ошибки сборки/загрузки.
Артефакты лежат в `tmp/space-tests/rv32i-io` и `tmp/space-tests/rv32i-io-c`.
Четыре проверки большого C-образа при O0/O2 и обоих способах загрузки
сохраняются в `tmp/space-tests/rv32i-memory`: двоичная программа больше
64 КиБ, статические данные занимают 256 КиБ, стек и вывод обращаются
к адресам выше прежней границы.
