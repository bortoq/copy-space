# C3_RUN MVP Shortcuts Inventory (Stage-23)

Status: inventory complete, remediation pending.
Source: `src/mkimage/std7_fixed/words_c3_run.c` (generated by `scripts/riscv/gen_c3_run.py`).

## Identified shortcut patterns
- Opcode filter is hard-wired to `0x13` (ADDI-family) in `write_page_opcheck`, with direct bitwise checks instead of a general decoder matrix.
- Register writeback in `write_page_addi` is hard-coded to `x1` (`G_REG_BASE + 32`) with explicit comment `For MVP (rd=1)`.
- Immediate handling is tailored to single-path ADDI flow and does not dispatch by funct3/funct7 families.
- PC update page uses a fixed 24-bit copy flow and skips full architectural progression logic.
- Step accounting explicitly skips increment implementation (`For MVP: skip full increment and let test set G_STEPS directly`).
- Budget page is effectively a no-op placeholder (`write_page_budget`).
- Stop-reason page writes fixed halt semantics without differentiated trap taxonomy.

## Blocking impact
- Non-trivial guest binaries can pass protocol/lifecycle checks while still bypassing full ISA semantics.
- Deterministic behavior can be observed for narrowed workloads but does not prove unified decode->execute correctness.

## Required remediation (tracked by roadmap stage 23)
- Replace single-opcode assumptions with unified decode/dispatch for the declared RV profile.
- Add explicit reject/trap path for unsupported decode tuples.
- Make step/pc/budget accounting architectural, not test-assisted.
