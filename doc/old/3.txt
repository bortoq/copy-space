1) Ключевые договорённости/уточнения
1.1 Определение “тика” в copyspace
В copyspace “тик” = исполнение всех PROCESSOR_N инструкций (например 64) за один шаг VM.
Это удобно: можно считать суммарную “полезную работу” за тик как сумму n по всем инструкциям.

Решили учитывать внутреннюю стоимость адресации как в vm1 (много слоёв compare-exchange).

2) Архитектурное направление: сделать “ASIC‑ближе”, сохраняя “адресацию без арифметики”
2.1 Главная рекомендация
Уйти от “каждая позиция (бит) имеет индекс/атрибуты и прогоняется через сеть” к split-plane:

Control plane: сортируем/маршрутизируем токены границ интервалов (O(K)), а не все N позиций.
Data plane: данные лежат в banked storage с широкой гранулярностью (слова 32/64/128 бит), копируются bulk, хвосты маскируются.
2.2 “Токены/границы” конкретно
Для каждого COPY_RANGE(dst_lo,dst_hi,src_lo,src_hi) создаются токены границ (обычно 4 на копию), сортируются по pos (лексикографически, без арифметики), затем sweep-line формирует толстые сегменты между границами.
Стоп-критерий копирования сегмента можно делать через сравнение “addr < next_boundary”; локальный счётчик/инкремент допустим как внутренняя микро-логика.

2.3 Для Forth/copycode
Чтобы использовать архитектуру эффективно, компиляция должна:

сливать мелкие копии в большие (fusion);
удалять мёртвые/промежуточные копии (DCE, copy propagation);
выравнивать буферы (ABI);
паковать операции в такты, соблюдая dst non-overlap.

3.2 Для copyspace (важнее всего, т.к. там EQ24P и реальные слова)
Предложено считать на каждом тике:

B_sum_tick = Σ n по всем PROCESSOR_N инструкциям (быстро, верхняя оценка).
B_uniq_dst_tick = длина объединения dst-интервалов [dst, dst+n) (точнее, диагностика overlap).
Реализуется дешёвым merge_and_count на ≤64 интервалах на тик.
Предложены CLI-флаги vmrun:

--report lat (default)
--report thr --from T0 --len L
опционально --report-hist
опционально --clock-hz для перевода в bits/s.
3.3 Для vm1 (опционально)
Сделать “аналитический” отчёт:

lat_microticks = C(N) (из LAYER_N и коэффициента)
bits_moved = Σ длины dst-интервалов за такт
bits_per_microtick = bits_moved / lat_microticks
Throughput mode: параметр --ii (initiation interval) для оценки steady-state: avg(bits_moved)/ii.
