1) Ключевые договорённости и выводы
1.1 Tick семантика в copyspace
1 tick VM = выполнение всех PROCESSOR_N слотов в vm_tick().
1.2 Метрики “толщины”
Решили считать две метрики на тик:

B_sum_tick = Σ n по всем copy в тике (верхняя оценка работы)
B_uniq_dst_tick = длина объединения dst-интервалов [dst, dst+n) (реальный объём записи + диагностика overlap)
На финальном отчёте:

latency: totals и averages по всем тикам
throughput: averages по steady-state окну FROM..FROM+LEN

2) Реализация vmrep в copyspace: статус
2.1 Почему отчёт сначала “не было видно”
scripts/test_all.sh редиректит stderr vmrun в файлы:
tmp/compile.log, tmp/run.log
поэтому [vmrep] был в логах, а не на экране.
2.2 Скрипты для удобства
Подготовлены правки scripts/test_all.sh: функция dump_vmrep() печатает блок [vmrep]..VMREP_END в консоль после compile/run (только если COPYSPACE_REPORT задан).
Подготовлен scripts/vmrep.sh: удобный запуск одного теста или всех тестов с env для окна FROM/LEN и (опционально) HZ.
3) Важный баг: vmrep hooks отсутствовали в реальном vm_tick()
Симптом: bench показывал ticks_total>0, но bits_sum_total=0.

Причина: авто-патч не вставил vmrep_note_copy(dst,n) в vm_tick().

3.1 Фикс
Сделан жёсткий “ensure” патч:

scripts/ensure_vmrep_hooks.sh гарантированно вставляет в vm_tick():
vmrep_tick_begin(vm->processor_n);
vmrep_note_copy(dst,n); перед bitcpy(...)
vmrep_tick_end(); перед return VM_OK;
После этого vmrep начал считать правильно.

4) Bench: “идеальный толстый слой” bulkcopy
4.1 Генерация образа без C (чтобы не упираться в компиляцию)
Сделан python-генератор image:

scripts/mkbench_bulkcopy.py
Он:
читает base image (out/img_fixed_pool_big.bin)
зануляет processor area
записывает в slot0 инструкцию copy(len_bits, dst, src)
инициализирует src паттерном, dst нулями
Запускатель:

scripts/bench_bulkcopy.sh
Он:
строит bench image
запускает vmrun на LIFE тиков
выводит [vmrep] на экран
4.2 Результат bulkcopy (успешно)
Для LEN_BYTES=65536 (64KiB, 524288 бит):

avg_bits_sum_per_tick = 524288
avg_bits_uniq_dst_per_tick = 524288
throughput окно (FROM=1000 LEN=5000) совпадает
Вывод: механизм отчёта и окно steady-state работают; это “верхний потолок” для толстого слоя.
