# Очистка артефактов

Решение: дополнить `.gitignore` для файлов сборки вне build/tmp/out:
пакетов stream/core, сопровождающих JSON, каталогов *.build, результатов OUT,
зависимостей компилятора, кэшей Python/CMake и установочных пакетов deb.
Корневые job.in и job.in.json — готовое задание и его описание; исходные
файлы *.in в других местах не считать артефактами автоматически.

`make clean` удаляет известные артефакты по всему проекту, включая build,
out, bak, dist и содержимое tmp, Python-кэши и результаты тестов.
Файлы, отслеживаемые Git, сохраняются даже внутри каталога артефактов.
Символические ссылки удаляются как ссылки, перехода за пределы проекта нет.
Настройки редактора, среды разработки и метаданные Git не удаляются.

Установленный компилятор в tmp/rv32i-toolchain/root сохраняется: это инструмент
повторной сборки. Установочные deb и прочие временные файлы рядом с ним
удаляются. Сохраняются закреплённые исходники pForth и встроенный словарь
runtime/pforth/pfdicdat.h с JSON: они являются входом обычной сборки,
их восстановление требует отдельной подготовки.

Очистка не использует безусловный `git clean -fdX`: игнорируемые пользовательские
данные и настройки не становятся мусором только из-за `.gitignore`.
Файлы с произвольными именами следует создавать в build/tmp/out, чтобы
очистка могла однозначно определить их назначение. Для очистки нужны Python 3
и Git; при невозможности получить перечень отслеживаемых файлов удаление
не начинается.

Сырые журналы zstd (`trace*.txt.zst`) также являются артефактами,
включая файлы вне tmp/build/out; добавить их в игнорирование и очистку.

Для сохранения доказательств при недостатке места допускается перекодировать
старый gzip-журнал в zstd. До замены читать оба полных потока, сравнить
число распакованных байтов и SHA-256. Сохранить archive.json с исходным
и новым именами, контрольными суммами и размерами; исходники, OUT, число
событий и прежнее evidence.json не менять. Только после проверки заменить
сжатый файл. Это не очистка сырых событий и не повторное исполнение.

Дампы старых завершённых проверок можно сжать gzip, сохранив все байты.
До удаления несжатого файла сверить SHA-256 полного распакованного дампа;
dump-archive.json сохраняет исходное имя, размер и контрольные суммы.
Чтобы повторить исходную команду проверки, восстановить space.bin из gzip.
Сырые журналы, IN/OUT и исходники при этом не удалять.

Проверить `make test-clean` в отдельном временном репозитории: удаление
артефактов, сохранение исходников, установленных инструментов и настроек,
обработку пробелов в именах, ссылок и повторный вызов очистки.

Проверка выполнена: `make test-clean` прошёл, включая отказ от удаления
без метаданных Git. Очистка рабочего проекта сохранила проверяемые суммы
всех 279 отслеживаемых файлов. После неё прошли `make bins` и `make pforth`.
Повторная очистка удалила созданные артефакты, следующий вызов не удалил
ничего. В tmp остался только установленный tmp/rv32i-toolchain/root.
