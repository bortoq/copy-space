# Компилятор C → копирования на pForth

Решение: реализовать первый компилятор подмножества C на pForth.
Разбор пользовательского C и генерация результата выполняются внутри
RV32I внутри пространства. Хост готовит только образ компилятора и
соединяет файлы IN/OUT. Эмулятор пространства не получает новой логики.

Результат — двоичный пакет для стандартного IN. При втором запуске
он загружает данные и слои копирований; RV32I и pForth в результирующем
пространстве отсутствуют. Общие таблицы и операции копирований можно
подготовить со словарём компилятора до чтения пользовательского C.
Подготовка этих постоянных частей не является компиляцией задания.

## Исходный объём языка

Этот раздел описывает первый этап. Последующие расширения языка и
действующий ABI, включая глобальные объекты, косвенные вызовы и обычный
возврат main, описаны в [linux_copy.md](linux_copy.md).

Скалярные типы выбранного ILP32: char, signed char, unsigned char,
short, unsigned short, int, unsigned int, long, unsigned long, _Bool,
void и указатели на эти типы, включая несколько уровней. Char знаковый;
char и signed char имеют разные описания. Целые литералы оснований 2/8/10/16,
локальные переменные, присваивания-выражения и составные присваивания,
префиксные и постфиксные ++/--, запятая, + - * / %, унарные + - ! ~,
сравнения == != < <= > >=, битовые & | ^ и сдвиги << >>,
логические && ||, условное выражение ?:, приведения между указанными
типами, блоки, if/else, while, do/while, for, break/continue, функции и return.
Доступны sizeof, _Alignof, __alignof/__alignof__,
typeof/__typeof/__typeof__ и GNU-выражения `({ ... })`.
Размер/выравнивание char и _Bool — один байт, short — два,
int/long/указателя — четыре. Запросы размера и выравнивания возвращают
unsigned int и не исполняют операнд. GNU размер/выравнивание void — один. typeof
сохраняет тип операнда без его исполнения. Типы переменного размера
пока отсутствуют. GNU-выражение возвращает последнее выражение блока;
если последнего выражения нет, его результат имеет тип void и может
быть отброшен. GNU sizeof такого результата равен 1. Функции void
поддерживают return без выражения и возврат выражения void.
main не принимает параметров и возвращает int. До вызова функцию нужно
определить или объявить прототипом. Доступны непосредственная и взаимная
рекурсия. Глобальные переменные и указатели на функции,
препроцессор и плавающая точка в этот этап не входят.
Перед арифметикой char/short/_Bool продвигаются в int. Ранг long выше int;
при равной ширине long и unsigned int общий тип — unsigned long.
При смешивании int и unsigned int результат — unsigned int.
Присваивание, аргумент и возврат преобразуются к типу назначения:
маленькое целое усекается с последующим знаковым/нулевым расширением,
_Bool нормализуется в 0 или 1. Сравнения учитывают
общий тип операндов. >> знакового int сохраняет знак; unsigned int
дополняется нулями. Знаковость сдвига определяется левым операндом.
Деление signed округляет к нулю, остаток сохраняет знак делимого.
&&, || и ?: исполняют только нужные операнды и ветви.
Переполнение сложения, вычитания и умножения задано по модулю 2^32.
Это явно ограниченное подмножество с указанной
семантикой переполнения, а не обещание полного стандарта C.
Деление на ноль и число разрядов сдвига вне 0..31 дают диагностику через
OUT и idle; прочие случаи неопределённого поведения C не становятся
разрешёнными. 64-битные типы и литералы LL не поддерживаются. L/l обозначает long,
U/u — unsigned, допустимы UL/LU в обоих регистрах. Hex/octal/binary
выбирают соответствующий unsigned-тип, если знаковый не вмещает значение;
несуффиксные hex/octal/binary выбирают
unsigned int, если значение превышает INT_MAX. Десятичный литерал без
суффикса, не помещающийся в int, пока отвергается, поскольку требует
ещё не реализованного более широкого типа. `signed` и `unsigned` можно
указывать с `int` или без него. Указатели unsigned int* пока отвергаются.
Доступны комментарии // и /* ... */, приоритеты операций и скобки.
Неинициализированная локальная переменная и завершение функции без
return дают ноль; это также явно заданное отличие от общего C.
После выхода из блока его локальные имена недоступны. Внутренний блок
может затенять внешнее имя, повторное объявление в одной области
отвергается. Объявление в инициализаторе for видно до конца цикла.
main нельзя вызывать как обычную функцию.

Присваивание имеет правую ассоциативность и возвращает rvalue типа
назначения. Составные присваивания и ++/-- вычисляют адрес назначения
один раз. Постфиксный оператор возвращает прежнее значение, префиксный —
новое. Запятая исполняет операнды слева направо. Несколько объявлений
одного базового типа можно разделять запятыми; запятые между аргументами
и объявлениями остаются разделителями. Continue выполняет изменение for
либо проверку while/do; break выходит из ближайшего цикла.

Каждый активный вызов имеет отдельный кадр локальных данных и адрес возврата.
Выражения сохраняют результаты вызовов в отдельных временных значениях.
Арифметика и сравнения вызывают общие слои копирований с LUT;
переходы выбирают следующий слой, без нового набора инструкций.

Доступны прототипы функций со скалярным, указательным и void-возвратом,
со скалярными и указательными параметрами, включая параметры
без имени. При определении имена обязательны. Повторные объявления
должны совпадать по типам и числу параметров. Вызванную функцию нужно
определить в этом же исходнике до завершения компиляции; неизвестные
и не определённые вызовы дают ошибку до выдачи пакета. Неиспользуемый
прототип разрешается. Пустой список `f()` в этом подмножестве означает
ноль параметров; старые объявления с неуказанным числом параметров
GNU C11 не поддерживаются. Раздельной компиляции пока нет.

Операции с указателями: &local, *pointer, запись через указатель,
передача параметров и возврат, сложение/вычитание целого индекса,
разность и сравнения. Шаг берётся из размера типа объекта. Указатели
содержат байтовые адреса. Void* неявно совместим с другими указателями;
несвязанные типы указателей при присваивании отвергаются. Явное приведение
между указателями допускается. GNU void*-арифметика использует шаг один;
разыменование void* пока запрещено. NULL задаётся нулевым целочисленным
литералом. Адрес локального объекта сохраняется при вызовах и рекурсии.
Чтение/запись char изменяет восемь бит, short — шестнадцать. unsigned char*
может читать и менять логические байты int; остальные байты сохраняются.
Физический байт дампа имеет обратный порядок битов относительно
логического байта C, а числа остаются little-endian. Побайтовая функция
копирования на C проверена прямым исполнением с GCC-эталоном.
Указатель на завершённый вызов и выход за отдельный объект, как в C,
не являются разрешёнными операциями; проверка диапазона этого не обнаруживает.
Правила ABI и цель Linux описаны в [linux_copy.md](linux_copy.md).

OUT результирующей программы — ровно четыре байта return из main,
в little-endian. Компилятор выдаёт пакет только после успешного разбора
всего C. Ошибка даёт текст с позицией исходного ввода и код завершения
гостя 2; частичный пакет не выдаётся. Текст C поступает после команды
запуска компилятора до EOF. Сборка компилятора не включает завершающую
запись OUT, чтобы не загрязнять двоичный результат.

Загрузчик результата проверяет число прочитанных байтов и признак ошибки
копирования внутри пространства. Неполный пакет не запускает main.
При обрыве основного блока OUT содержит `copy-c: load error` и перевод
строки (19 байт, отличный от любого четырёхбайтового результата); при обрыве
установочной записи стандартный core выдаёт свою запись C/1.

## Сборка и два запуска

```sh
make copy-c-job COPY_C_SOURCE=examples/copy_c/sum.c
build/bin/space-64m < build/copy-c/job.in > build/copy-c/program.in
build/bin/space < build/copy-c/program.in > build/copy-c/result.out
```

В примере result.out содержит `03 00 00 00`. Для цикла заменить исходник
на `examples/copy_c/loop.c`: ожидается `0F 00 00 00` (15).
`COPY_C_JOB` меняет путь задания, по умолчанию `build/copy-c/job.in`.
Пакет компилятора используется повторно для разных исходников.
`scripts/copy_c/job.py` только соединяет готовый образ, команду CC-RUN
и исходные байты C; Python не разбирает C и не генерирует копирования.

При первом `make copy-c` нужен GCC с `-m32` и Linux с разрешёнными
системными вызовами i386 для подготовки словаря; 32-битная libc не нужна.
Словарь создаётся только в build/copy-c/compiler.stream.build/dictionary.
Исходники обычного pForth и его сохранённый словарь не заменяются.
Затем требуется RISC-V GCC и binutils по [build.md](build.md).
Подготовка общих таблиц, слоёв и слов Forth выполняется до подачи C.
При каждом запуске CC-RUN заново устанавливает адреса рабочих буферов
в загруженном словаре, чтобы не использовать адреса процесса подготовки.

Гостевые слова CS-READ, CS-WRITE и CS-EXIT добавлены только в сборку
компилятора; они вызывают существующие ECALL гостевого runtime.
CS-PUT-BITS упаковывает выбранные поля в память гостя и сохраняет
остальные биты байта. Его C-функция включена в загруженный RV32I-образ
и исполняется копированиями. Разбор C, описания типов, размещение данных
и выбор копирований/слоёв находятся в runtime/copy_c/compiler.fth.
Ядро эмулятора не расширяется. SHA-256 custom.c входит в условия
повторной подготовки словаря.

## Ограничения памяти

Исходник — до 1048576 байт, имя — до 31 байта, функций — до 16,
параметров — до 8, локальных имён в функции — до 128.
Глубина вложенности — до 32. Для переменных, результатов функций и
временных значений выделены 2048 байт в кадре. Объекты используют свой
размер и выравнивание; временные значения — выровненные четыре байта.
Допускается до 128 вызовов, адрес определения которых ещё не известен
при разборе вызова.
Для констант и таблиц переходов — 512 слов; пары адресов выровнены
на 64 бита. Буфер кода — 128 слоёв по 256 инструкций, включая общие
операции. Служебные слоты и место для переходов уменьшают полезную
вместимость. При исчерпании области компиляция завершается ошибкой.

Образ компилятора использует space-64m: 64 МиБ пространства,
16 МиБ гостевой памяти, 256 инструкций и поля 28/29/29 бита.
Подготовка словаря выделяет 2 МиБ кода, 64 КиБ имён и пул 4 МиБ;
готовый словарь сохраняет 8 КиБ резерва кода и 4 КиБ имён.
Это запас для дальнейшего расширения языка; достаточность для Linux
пока не доказана. Прямой результат по-прежнему использует обычный
space на 2 МиБ с полями 23/24/24 бита.
Загружаемые данные результата начинаются с бита 98304, виртуальные
кадры — с 131072, код — с 262144. Байты 12288..16383 отведены
под строки со статическим временем жизни.
Служебные значения находятся в нижней части пространства;
локальные значения — в кадрах верхнего МиБ. Размер кадра —
2048 байт, доступно 512 кадров, включая main. Указатель кадра хранится
в битах 152128..152159. Доступ к кадру реализован подстановкой его адреса
в поля копирований. Кадр начинается с 32-битного адреса возврата и 64-битного результата;
первый параметр или объект имеет битовое смещение 96. Скалярный аргумент
передаётся в 32 или 64 разрядах в зависимости от типа. Дополнительные
аргументы упакованы по четыре или восемь байтов с выравниванием четыре.
Переполнение стека даёт `copy-c: stack overflow` и idle; разыменование NULL, неверного диапазона или выравнивания —
`copy-c: pointer error` и idle. Указатели могут обращаться к
верхнему МиБ и области строк; выравнивание проверяется по типу объекта. Последний байт
и последнее 16-битное слово проверены отдельными сырыми журналами.
Служебные данные и код недоступны.
Отдельная защита загрузки установлена в битах 7340032 (данные)
и 7372800 (два слоя кода), после всей области кода C и перед стеком;
её нельзя потерять при обрыве основного блока.
Установочные записи используют существующий протокол стандартного core.

## Проверки

Проверить одинаковый результат компиляции на настоящем pForth для
подготовки и на гостевом pForth. Проверки на хосте служат только быстрыми
регрессиями: доказательство компиляции — входной C, OUT-пакет, дамп
и сырой журнал копирований гостевого запуска. Отдельно исполнить
полученный пакет стандартным space с сырым журналом и сравнить return.
Проверить перенос, знаковые границы, вызовы, вложенные условия и цикл,
ошибки синтаксиса, ограничения буферов и обрыв пакета.

`make test-copy-c` выполняет быстрые регрессии настоящего 32-битного
pForth и сквозные гостевые проверки; `--native-only` у
`tests/test_copy_c.py` оставляет только быстрые проверки и не является
доказательством компиляции внутри пространства.
В `tmp/space-tests/copy-c` сохраняются входы, команды, OUT, дампы
и журналы; гостевые журналы сжаты без потери событий.
По умолчанию используется gzip; `--trace-compression zstd` выбирает zstd
и требует одноимённую программу. Аудит распаковывает весь журнал и
проверяет завершение, число копирований и событий каналов.
Тесты долго выполняются и создают большие журналы, поэтому не включены
в обычный `make test`. Все артефакты удаляются `make clean`.
Гостевые сценарии по умолчанию: sum, pointer-guest и syntax-error.
Прочие сценарии выбираются через `--guest-case`; предел времени одного
гостевого запуска задаётся --guest-timeout (по умолчанию 3600 с).
--ticks-per-segment N сохраняет полный дамп каждые N тактов и продолжает
его через существующий --core. Каждый полный журнал части сохраняется
отдельно; логические позиции каналов берутся из фактических событий,
а не из чтения stdio вперёд. Проверка продолжения сравнивает всю память
и OUT с непрерывным запуском. --resume-segments продолжает уже сохранённые
полные части в том же --artifacts с теми же параметрами. До продолжения
сверяются контрольные суммы IN, эмулятора, первоначального core и дампа,
а также длина OUT; незавершённые части не используются. После добавления кадров генерация выдаёт
больше копирований, поэтому прежний предел 1800 с увеличен.

## Массивы и постоянные размеры

Поддержаны локальные массивы скаляров и указателей, вложенные измерения,
индексирование a[i] и i[a], адрес элемента и адрес всего массива через
&array/typeof. Размер и выравнивание описания типа хранятся в 32-битных
ячейках. Размер массива вычисляется компилятором из целочисленного
постоянного выражения, используя те же приоритеты, приведения, sizeof,
деление и короткое замыкание, что и обычный разбор C. Выполнение
локальной переменной, присваивания или вызова не является постоянным
размером. Динамические массивы пока отвергаются.

sizeof/typeof сохраняют весь тип массива; в обычном выражении он
преобразуется в указатель на первый элемент. Параметр int a[3] либо
int a[] преобразуется в int*; sizeof параметра равен четырём. Пустой
размер допустим в параметре, а sizeof неполного массива отвергается.
&*p возвращает адрес без чтения памяти, включая NULL. GNU-блок сохраняет
скалярное lvalue, но массив в его результате преобразуется в указатель.

присваивать или увеличивать. Нулевые размеры GNU, designated
инициализаторы и вывод размера из инициализатора

## Структуры и объединения

Добавлено естественное размещение ILP32: поле выравнивается по своему
типу, итоговый размер — по наибольшему выравниванию поля. В объединении
поля начинаются с нулевого смещения. Поддержаны вложенные структуры,

## Проверка выражений, циклов и областей видимости

```sh
python3 tests/test_copy_c.py --native-only --gcc-reference --artifacts tmp/space-tests/copy-c-expressions-native
python3 tests/test_copy_c.py --guest-case gnu-expr-guest --trace-compression zstd --artifacts tmp/space-tests/copy-c-expressions-guest
```

Первая команда прошла: 220 корректных программ, 77 проверок отказа,
переполнение стека, пять ошибок указателей, три обрыва пакета и пять
арифметических ошибок. Сохранены 234 полных сырых журнала прямого
исполнения результатов. 219 результатов совпали с GCC для ABI 32 бит
под `-std=gnu11 -fwrapv`; заданный проектом возврат без return проверен
отдельно. Проверены вычисление адреса lvalue один раз, вложенные циклы
с break/continue, затенение, восстановление видимости после for,
невычисляемые sizeof/typeof и GNU-выражения, в том числе результат void.
Проверены допустимая глубина 32 и отказ при её превышении.

SHA-256 проверенного compiler.fth:
cd7a03acede5860c465e94e51776e49acaa02a93b53afb77d9a205d83c4aacea.

Вторая команда — сквозная проверка примера
`examples/copy_c/gnu_expressions.c`, ожидаемый результат 7 (`07000000`).

Гость завершился с кодом 0. OUT-пакет размером 197640 байт побайтно совпал
с проверочным pForth. Отдельное исполнение прямыми копированиями выдало
`07000000` и остановилось по idle за 768 тактов.

Полный сырой журнал содержит 1242444110 копирований и 2662 события

Сохранены полный IN, исходник, образ, OUT-пакет, дамп и журнал; отдельно
