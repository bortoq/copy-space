## (3) TERM0 descriptor ABI spec
```markdown
# doc/45_term0_descriptor_abi.md — TERM0 device descriptor + CHN1 headers (ABI) — 2026-05-05

## 1. Цель
Зафиксировать ABI layout self-describing terminal device (TERM0), который публикуется через ART и располагается в bus-region внутри `space`.

Контракт нужен, чтобы “доказательство, что 3 канала принадлежат 1 устройству” выполнялось полностью на стороне `space`, без логики эмулятора.

## 2. Публикация через ART (append-only)
- `ART[65] = BUS_BASE` — база bus region (bitaddr)
- `ART[66] = TERM0_DESC` — адрес device descriptor терминала (bitaddr)

## 3. Размещение в bus region (TERM0 v1)
Рекомендуемое размещение (byte-aligned):
- `TERM0_DESC = BUS_BASE`
- `TERM0_CH_IN  = BUS_BASE + 64*8`
- `TERM0_CH_OUT = BUS_BASE + 96*8`
- `TERM0_CH_ERR = BUS_BASE + 128*8`

(Конкретные offsets могут меняться, но должны быть согласованы с mkimage; bus region должен быть зарезервирован от overlap с pool/scratch.)

## 4. Device descriptor format: `CDEV` (v1)
Descriptor хранится как байтовая структура (в `space`, byte-aligned).

### 4.1 Заголовок `CDEV`
Offsets (bytes):
- `0x00` magic u32 = `0x43444556` ("CDEV")
- `0x04` version u16 = `1`
- `0x06` dev_type u16 = `1` (TERM)
- `0x08` device_id u64 (instance id)
- `0x10` port_count u8 = `3`

### 4.2 Таблица портов
Ports array начинается с `0x14` (20 decimal).
Каждая запись порта размером 8 байт:

- `+0` port_id u8:
  - 0 = stdin
  - 1 = stdout
  - 2 = stderr
- `+1` proto u8 = `1` (CHN1)
- `+2` flags u16 (пока 0)
- `+4` chan_base = bitaddr (`ADDR_BITS` шириной; обычно 24-bit)

Тем самым descriptor сам перечисляет все каналы устройства.

## 5. Channel header format: `CHN1` (v1)
Каждый `chan_base` указывает на channel header, который должен быть self-identifying.

Минимальные требования (чтобы можно было валидировать устройство):
- в начале header:
  - magic u32 = `0x43484E31` ("CHN1")
- channel header должен однозначно соответствовать `device_id` и `port_id` из descriptor (рекомендуется хранить их в header).

Рекомендуемый layout `CHN1` v1 (если фиксируете сейчас):
- `0x00` magic u32 = "CHN1"
- `0x04` version u16 = 1
- `0x06` reserved u16 = 0
- `0x08` device_id u64
- `0x10` port_id u8
- `0x11` proto u8 (=1)
- `0x12` flags u16
- далее поля протокола (REQ/DONE/ERR/SEQ/LEN/BUF_PTR и т.п.) — как отдельная спецификация протокола.

Если вы пока не готовы фиксировать протокол полностью, допускается считать “после `flags` область зарезервирована”, но `device_id/port_id` лучше зафиксировать сразу, чтобы доказательство device≠channel было строгим.

## 6. Правило валидации “3 канала = 1 устройство”
Код в `space` (или validator) может доказать принадлежность:
1) Прочитать `TERM0_DESC` из ART.
2) Проверить `CDEV` magic/version/type.
3) Для каждого порта `i`:
   - взять `chan_base` из ports[i]
   - проверить `CHN1` magic по адресу `chan_base`
   - (если fields зафиксированы) проверить `chan.device_id == desc.device_id` и `chan.port_id == ports[i].port_id`.

Это доказательство не требует участия эмулятора.
