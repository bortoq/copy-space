# pForth на RV32I

Решение: перенести pForth как программу C в гостевую память 512 КиБ.
Исходники официального проекта сохранить в third_party/pforth с лицензией
и точной ревизией e5617638c3a397c644fe82c6301711867a0ca1bf.
Код эмулятора пространства и набор инструкций RV32I не расширять.

Отключить стандартную библиотеку, файловую систему и числа с плавающей
точкой. Использовать собственный распределитель pForth в статическом
буфере. Символьный ввод/вывод заменить cs_read/cs_write. Ошибки вывода
и утверждений завершают гостевую программу через cs_exit.

Словарь содержит 32-битные little-endian значения. Подготовить его настоящей
32-битной сборкой pForth без зависимости от 32-битной libc. Внешняя подготовка
словаря является сборкой артефакта, а не исполнением пользовательского Forth
при запуске пространства. Сохранить источники, команды и проверяемую сумму
подготовленного словаря. Системные определения брать из system.fth до
раздела Auto Initialization: арифметика, условия, циклы, переменные,
определения слов и строки; определения файловой системы не включать.

Исходный C-код pForth не изменён. `runtime/pforth/core.c` заменяет один
безусловный вызов strlen на собственный pfCStringLength через обёртку
препроцессора; совместимые заголовки закрывают неиспользуемые зависимости
stdio/sys/types/assert. Предупреждения upstream о типах и выключенных
функциях сохраняются в compile.stderr, но не останавливают сборку.

Сохранён словарь с 6140 байтами имён и 5328 байтами кода. При запуске
он уже находится в изменяемых массивах гостевого образа: резерв для новых
имён — 32768 байт, для нового кода и данных — 65536 байт. Общий буфер
распределителя pForth — 65536 байт; стек данных и стек возвратов — по
512 значений. Это позволяет избежать повторной компиляции и копирования
словаря при каждом запуске.

Гостевой запуск загружает встроенный словарь и читает пользовательские
строки через IN. EOF завершает программу; BYE завершает немедленно.
Проверять завершение последней строки без перевода строки, слишком длинные
строки, незавершённое определение, ошибки ввода/вывода и неизвестное слово.
Все вычисления пользователя выполняются интерпретатором на RV32I,
который выполняется копированиями пространства. OUT содержит
результат программы и сообщения её ошибок, без эха и приглашений.
В режиме готового задания добавляется завершающая запись.

Добавить воспроизводимые команды подготовки/сборки и запуск через обычный
IN без --core. Проверить сложение, переполнение 32 бит, определения слов,
условия, DO/LOOP, переменные, чтение/запись памяти и повторное использование
словаря. Сохранять IN/OUT, дампы, команды и сырые журналы копирований.

## Сборка и запуск

Основной путь для готового задания — один файл IN и прямой запуск:

```sh
make pforth-job TASK=examples/pforth/demo.fth JOB=build/pforth/demo.in
build/bin/space < build/pforth/demo.in > result.out
```

Файл OUT содержит результаты Forth, затем завершающую запись
`[space:R:0000000A:00000000]` с переводами строк. Формат, ошибки и прямые
проверки описаны в [file_job.md](file_job.md). При исполнении не нужны
Python-оболочка, JSON или чтение дампа пространства.

Для пакета без включённого задания и без завершающей записи:

```sh
make pforth
printf '1 2 + . cr bye\n' | python3 scripts/rv32i/run.py --stream build/pforth/pforth.stream
```

Выводит `3` и завершается с кодом 0; пробел после числа и дополнительный
перевод строки на BYE — поведение pForth. Для примера с определением слова
и циклом:

```sh
python3 scripts/rv32i/run.py --stream build/pforth/pforth.stream < examples/pforth/demo.fth
```

Без перенаправления ввода можно вводить строки вручную. Приглашение и эхо
отключены; терминал хоста сам отображает вводимые символы. `BYE` завершает
процесс, даже если IN остаётся открытым. Последняя строка без перевода
строки исполняется при EOF. Максимальная длина строки — 255 байт.
Шестнадцатеричные цифры A..F задаются в верхнем регистре.

`scripts/pforth/build.py -o FILE` создаёт пакет IN, `--core` — исходный образ
для `space --core`. Поддерживаются `--compiler` и `--optimization`.
Обычная сборка использует сохранённый словарь и не требует сети, ОС в госте
или внешнего интерпретатора при исполнении Forth.
Образ программы занимает 136028 байт, пакет IN — 502333 байта;
гостевая память — 512 КиБ, полное пространство — 2 МиБ.

`scripts/pforth/prepare.py` заново создаёт runtime/pforth/pfdicdat.h и JSON
с проверяемыми суммами. Для подготовки нужен GCC с генерацией i386 и Linux,
разрешающий выполнение системных вызовов i386; 32-битная libc не нужна.
В ограниченной песочнице эти вызовы могут быть запрещены: в данной среде
подготовка была выполнена вне такой песочницы. Артефакты подготовки —
tmp/pforth-prepare. Повторная подготовка дала те же байты словаря и JSON.

## Ограничения и проверка

Доступны целочисленные определения, условия, циклы, переменные, память
и строки из выбранного системного словаря. Файловые операции и числа
с плавающей точкой не предоставляются; это не полный ANS Forth.
Ввод и вывод используют только IN/OUT; ожидание реального времени и
проверка готовности терминала не реализованы. Время исполнения велико:
простая строка сложения с BYE в этой среде заняла около 43 секунд без
журнала; сложная сессия требует нескольких минут.

Коды завершения: 0 — EOF или обычный BYE; 1 — ошибка IN/OUT;
2 — неизвестное слово, ошибка определения или длины строки;
3 — ошибка запуска pForth; 70 — нарушение проверяемого утверждения.
Значение BYE-CODE также можно задать из Forth. Диагностика языка идёт
в OUT, диагностика внешней оболочки — в stderr.

`make test-pforth` сохраняет полные сырые события копирований в
tmp/space-tests/pforth/*/trace.txt.gz. Сжатие не отбрасывает события;
журналы читаются через gzip/zcat. Сохраняются также вход, выход,
конечное пространство, команды и результаты. Из-за исполнения копированиями
этот набор существенно медленнее обычной регрессии `make test`.

Основная сессия проверила сложение, умножение, переполнение 32 бит,
IF/ELSE, DO/LOOP, BEGIN/UNTIL, переменную, доступ к выделенным 60000 байтам
и BYE при открытом IN. Новые имена SQUARE, SIGN-TEST, SUM-TEN и AREA
отсутствуют в исходном образе программы и присутствуют в конечной гостевой
памяти. Полный журнал содержит 490715307 копирований, 3054 события каналов
и `stop 7207226 idle`; результат — в
`tmp/space-tests/pforth/live-language/result.json`.

`make test-pforth` прошёл все семь выполнений, включая последнюю строку
без перевода строки, неизвестное слово, незавершённое определение,
длинную строку и ошибки IN/OUT. Регрессии `make test` и
`make test-rv32i-c` также прошли; журналы — `tmp/pforth-tests.log`,
`tmp/pforth-space-regression.log` и `tmp/pforth-c-regression.log`.
