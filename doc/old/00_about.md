# Copy-Space / Forth0 — о проекте (общая информация)

## Идея
Проект исследует вычисления в модели, где базовая операция — **копирование битов** в общем адресном пространстве `space`.

VM содержит:
- память `space` (бит-адресуемая),
- “процессорную область” из N слотов инструкций `copy(n,dst,src)`,
- тики VM, в каждом из которых выполняются слоты процессора и обслуживается MMIO-handshake (stdin/stdout/halt).

Поверх этого строятся “внутренние” алгоритмы (слова/страницы/компилятор) как программы внутри `space`, сохраняя минимальность VM.

## Два подхода к вычислению

### 1) Layer-chain world (параллельные слои)
Программа — набор слоёв, каждый слой состоит из copy-инструкций. Слой трактуется как “параллельный шаг” при соблюдении инвариантов (например отсутствие конфликтов записи по dst).

Этот путь нужен для:
- моделирования “чистой” параллельной логики,
- будущей связи с hardware-идеями (deterministic permutation / parallel addressing).

### 2) Forth0 world (threaded code)
Ускоряющий путь для наращивания функциональности:
- есть интерпретатор Forth0 в `space` (threaded code),
- “слова” — страницы (processor images),
- программа — список cells `(code_ptr,next_ptr)`,
- есть token-компилятор, который строит список cells из потока токенов.

Так удобнее быстро добавлять stdlib: арифметику/сравнения/указатели/ветвления.

## Новый принцип дизайна: «всё внешнее — устройство, доступ через каналы»
Чтобы упорядочить работу с вложенными пространствами и внешними ресурсами, проект фиксирует архитектурное направление:

- **Устройство (device)** — это объект с идентичностью (device_id), типом и набором портов.
- **Канал (channel)** — это порт устройства (endpoint) с протоколом обмена (handshake + буфер/указатель).
- Модули/гесты/ОС оформляются как изолированные адресные пространства, но взаимодействуют с миром **через каналы**.
- “Менеджер каналов/устройств” — отдельная логика, отделённая от прикладной логики:
  - маршрутизирует сообщения,
  - выполняет цензуру/валидацию запросов,
  - обеспечивает location transparency: прикладному коду всё равно, “внешнее устройство” или “внутренний гест”.

Детерминизм сохраняется, т.к. каналы и их состояния — часть `space` (не внешняя недетерминированная среда).

См. `doc/40_devices_channels.md`.

## Что считается успехом
- VM остаётся простой (copy + MMIO).
- “Сложность” наращивается внутри `space` как программы/слова.
- Адреса/ABI слов и workspace фиксируются и документируются.
- Появляется согласованная модель устройств/каналов/гестов и канал-менеджер.
- Тесты и бенчи подтверждают корректность и регрессию.

## Репозиторий (clean baseline)
Baseline проекта ориентирован на Forth0 и содержит:
- VM ядро + инструменты запуска/подготовки,
- mkimage std7_fixed с фиксированными адресами слов (не зависят от POOL_CELLS),
- токен-тесты (fulladder/add8/add24/eq24/lt24/eq24p),
- vmrep-отчёт и throughput-бенчи (bulk/pack/permute).

См. `doc/10_state_std7_fixed.md` и `doc/30_bench_vmrep.md`.
