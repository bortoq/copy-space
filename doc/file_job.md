# Задание из одного файла IN

Решение: запускать готовое задание командой `build/bin/space < job.in > result.out`.
Хост при исполнении обслуживает пространство и каналы. Сборка образов
остаётся отдельным подготовительным действием; Python-оболочка запуска,
чтение дампа и декодирование регистров для получения результата не нужны.

Файл IN содержит установочные записи, загрузчик и RV32I, машинный образ
pForth со словарём, затем пользовательский Forth-текст. Сборка с `--task FILE`
объединяет эти части и включает завершающую запись OUT. EOF завершает
последнюю строку; BYE останавливает исполнение, оставшиеся байты не исполняются.
Сохранить прежний режим сборки пакета без задания и без завершающей записи.

Завершающая запись OUT имеет вид `\n[space:R:0000000A:00000000]\n`.
Её длина — 29 байт; при завершённом выводе она занимает последние 29 байт OUT.
Оба числа — восемь шестнадцатеричных цифр в верхнем регистре.
Первая буква обозначает этап: C — стандартный core, L — загрузчик,
R — RV32I. Первое число: C/1 — неполная или ошибочная установочная запись;
L/11 — ошибка загрузки RV32I, заголовка или программы; R/1..9 — причина
исключения RV32I; R/10 — завершение гостевой программы. Второе число:
для C/L — ноль; для исключения R — pc; для завершения R — гостевой код
завершения. Для pForth ноль означает успех, остальные коды описаны в pforth.md.

Запись формируют копирования core, загрузчика и RV32I. Эмулятор пространства
не знает этого формата. Его код процесса сообщает только об ошибке механизма
исполнения; остановка пространства сама по себе не означает успех задания.
Успех задания pForth подтверждает полная последняя запись R/10/0.
Данные результата предшествуют записи. При недоступном OUT, внешнем
прерывании или остановке по пределу тактов записи может не быть: отсутствие
полной записи не подтверждает успех. Файловые операции хоста до открытия
каналов по-прежнему относятся к окружению запуска.

Стандартный core по ошибке выбирает из таблицы слой с постоянной записью
C/1, выдаёт её на следующем такте и очищает инструкции. Адреса буфера и
повторного входа, размер установочной записи и успешный путь сохраняются.
Неполная запись больше не останавливается молча; это изменение относится
также к старым пакетам. Записи L/R включаются в образах заданий и через
необязательный `--report-status`; старый гостевой вывод сохраняется.

Добавить проверки прямого файлового запуска: определения и вычисления,
последняя строка, BYE, ошибки языка, обрывы всех этапов загрузки,
исключение RV32I и ошибки каналов. Сохранить полные сырые журналы,
команды, IN/OUT и дампы. Вердикт задания получать из OUT, дамп использовать
для независимой проверки записи.

## Сборка и запуск

```sh
make pforth-job TASK=examples/pforth/demo.fth JOB=build/pforth/demo.in
build/bin/space < build/pforth/demo.in > result.out
```

Либо явно: `python3 scripts/pforth/build.py --task task.fth -o job.in`.
`--task` включает завершающую запись автоматически; `--core` с ним
несовместим. Файл задания не должен совпадать с выходным файлом сборки.
JSON рядом с образом содержит границу Forth-текста, его длину и SHA-256,
общий размер и признак `report_status`. Он нужен для проверки сборки,
при исполнении эмулятор его не читает.

Для C и сырых образов RV32I доступен `--report-status` в
`scripts/rv32i/build.py`, `modules/rv32i.py` и `modules/rv32i_stream.py`.
Завершающая запись несовместима с контрольными кадрами `--state-output`.

`make test-file-job` запускает непосредственно `build/bin/space` с файловыми
stdin/stdout. Python в тесте готовит вход, наблюдает завершение и проверяет
артефакты; он не пересылает вход и не исполняет гостевые инструкции.
Артефакты — `tmp/space-tests/file-job`: для каждого выполнения сохраняются
job.in, result.out, space.bin, args.json, stderr.txt, result.json и полный
сжатый trace.txt.gz. Для недоступного OUT результат не сохраняется;
неполная/ошибочная передача проверяется по сырым событиям каналов.

Для проверки только загрузки и RV32I без длительных запусков Forth:
`python3 tests/test_file_job.py --skip-pforth`. Этот режим не заменяет
полный `make test-file-job`.

## Результат проверки

Полный `make test-file-job` прошёл 26 прямых выполнений, включая девять
причин исключения RV32I, отдельный ненулевой pc, полный 32-битный BYE-CODE,
ошибки каналов и остановку без завершающей записи по пределу тактов.
Основное Forth-задание вывело `49`, `6`, `3`, затем запись R/10/0.
Его полный журнал содержит 156396934 копирования, 2812 событий каналов
и `stop 2303362 idle`. Имена FILE-SQUARE и FILE-TALLY появились в гостевой
памяти и отсутствуют в исходном машинном образе.

Регрессии `make test` и `make test-rv32i-c` прошли. Журналы команд —
`tmp/file-job-tests.log`, `tmp/file-job-space-regression.log`,
`tmp/file-job-c-regression.log`. Сборка без задания сохраняет прежний пакет:
при сравнении с предыдущей сборкой различается только встроенная строка
времени сборки upstream pForth (`__TIME__`), вычисления и формат не изменены.
