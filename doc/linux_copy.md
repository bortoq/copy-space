# GNU C и Linux непосредственно в копированиях

Запрошенный результат: компилятор работает внутри пространства и выдаёт
копирования; готовый Linux также работает копированиями, без RV32.
RV32I/pForth допустимы как существующая среда выполнения компилятора.
Хост выполняет только эмулятор и обслуживает его файловые каналы.

После короткой проверки 14 октября 2026 основным путём выбран GCC с
генератором прямых копирований и Linux 6.12 NOMMU. TCC не выбран из-за
подтверждённых несовместимостей inline, внешних символов и обязательных
макросов ядра. [Отчёт и воспроизводимые проверки](tcc_feasibility.md).
Это выбор дальнейшей реализации: порт GCC и запуск Linux ещё не выполнены.

Сравнение Buildroot/µClinux/Tiny Core (14 октября 2026): для первого
запуска использовать выбранный Linux 6.12 без MMU, подход µClinux.
NOMMU уже поддерживается основным ядром; отдельный старый набор
uclinux-dist не нужен для выбора модели памяти. Buildroot — система
сборки ядра, toolchain и root filesystem, не отдельное ядро. Рассмотреть
его позднее для минимального init, libc и BusyBox после запуска ядра.
Tiny Core не снимает требования к новому arch/copyspace и ABI; размер
готового дистрибутива не определяет сложность этого переноса.
Источник Buildroot: https://buildroot.org/downloads/manual/manual.html.
Источник Linux: https://docs.kernel.org/admin-guide/mm/nommu-mmap.html.
Это рекомендация по последовательности, не заявление о готовности
Buildroot для нашей архитектуры. Обычный Buildroot исполняет сборочные
инструменты на хосте; при его применении сохранить исходное требование
компиляции внутри пространства, интегрировав гостевой toolchain и
необходимые инструменты. Собственный порт libc и загрузчик программ
также остаются необходимыми. NOMMU ограничивает mmap и не предоставляет
обычный fork; пользовательскую среду выбирать с учётом vfork/exec.

Это незавершённая работа. Компилятор подмножества из [copy_c.md](copy_c.md)
пока не способен собрать Linux. Добавление нескольких конструкций C
не означает поддержку GNU C или успешную сборку ядра.

Короткая проверка выбора TCC/GCC начата 14 октября 2026 в 09:16:59 UTC;
предел — 12 часов, до 21:16:59 UTC. Проверяется закреплённый снимок TCC
43c7708b85681a2fd4451c8a541af4494a8919b2 и исходный Linux 6.12.
Исследовательские сборки на хосте допустимы только как контроль: они
не доказывают исполнение компилятора или ядра внутри пространства.
Материалы хранить на data/work; сохранить исходники, конфигурацию,
команды, stdout/stderr, объектные файлы и SHA-256. До реализации полного
генератора проверить реальные исходники ядра и семантику inline,
атрибутов, встроенных функций и раздельной компиляции. Отделять ошибки
подготовки, ограничения архитектуры контрольного компилятора и ошибки
языка. Пробы с изменёнными заголовками отмечать отдельно и сохранять diff.
Продолжать TCC только при ограниченном списке исправлений; необходимость
серьёзно изменять обязательную семантику или структуру компилятора —

Это выбор начальной конфигурации, а не утверждение её работоспособности.

Целевой ABI остаётся 32-битным: указатели, int и long имеют 32 бита.

в таком ABI; его операции должны выполняться последовательностями
копирований. Наличие готового 32-битного Tiny Core для x86 не заменяет
порт ядра: его машинный код требует x86, а наш результат должен состоять
из прямых копирований.

## Switch и метки case

Добавить switch для нынешних целых типов. Управляющее выражение вычислять
один раз после целочисленных продвижений. Перед телом перейти к проверкам
case; проверки разместить после тела и направить в отмеченные места тела.
Так сохраняется последовательное выполнение соседних case, в том числе
когда default находится между ними. При отсутствии совпадения перейти
к default либо за switch. Значения case приводить к продвинутому типу
управляющего выражения; повтор и перекрытие диапазонов GNU запрещать.
Пустой диапазон GNU не выбирается. Сравнение границ учитывать знаковость.
Для каждого вложенного switch хранить собственные значения и адреса case.
Запретить переход к case внутри вложенного GNU-выражения из операторов;
switch внутри такого выражения допускается.
Break направлять за ближайший цикл или switch, а continue — в ближайший
цикл, в том числе через вложенный switch. Не объявлять этим поддержку goto,
меток обычного перехода, 64-битных управляющих выражений или полного GNU C.
Сверить с GCC и исполнением прямых копирований, затем запустить компиляцию
одного примера внутри пространства с полными журналами.

## Goto и метки перехода

Добавить обычный goto с именованной меткой в той же функции. Имена меток
хранить отдельно от объектов, typedef и меток типов; область имени —
вся функция. Запоминать адрес каждой метки и поле каждого перехода,
заполнять переходы после разбора тела. Разрешить переходы вперёд, назад,
через границы обычных блоков и из GNU-выражения из операторов наружу.
Повторное определение метки и несуществующую цель отвергать, включая
невыполняемые операнды sizeof и невыбранные ветви _Generic.
Чтобы запретить вход в GNU-выражение из операторов, сохранять отдельное
описание вложенности каждого такого выражения, а не только его глубину:
вход в соседнее выражение также запрещён. Переходы из невыполняемых
операндов проверять, но не создавать для них исполняемые копирования.
Для текущих размеров таблиц принять 128 меток и 256 переходов на функцию,
512 GNU-выражений из операторов; превышение явно отклонять.
Как в проверенном GCC gnu11, метка перед закрывающей скобкой блока
обозначает пустой оператор; это применяется также к case и default.
Computed goto, адреса меток, asm goto, VLA и cleanup ещё требуют отдельных
частей GNU C. Проверить обычные переходы с GCC и полными журналами
исполнения прямых копирований, затем запустить компиляцию внутри пространства.

## Декларации для указателей на функции

Сначала объединить разбор имён объектов, скобок, указателей и массивов
в один разбор declarator. Хранить последовательность преобразований от
имени наружу, затем применять её в обратном порядке к исходному типу.
Так различать `int *a[3]` и `int (*a)[3]`, включая вложенные скобки,
квалификаторы указателей, typedef, поля, параметры и абстрактные типы
sizeof/typeof, приведений и встроенных запросов типов. Выражение размера
массива разбирать один раз: повторный просмотр не должен повторно
определять типы внутри sizeof. Проверять размер и полноту элементов.
Принять текущий предел 32 преобразования и 32 вложенных разбора.
Затем добавить в тот же разбор функцию как отдельный тип с возвращаемым
типом и списком параметров, адреса функций и косвенный вызов по этому
описанию. До этого функциональную часть declarator явно отвергать;
прежние прямые объявления функций продолжают использовать нынешний ABI.
Поддержка скобок и массивов отдельно не означает готовность косвенных
вызовов или компиляции Linux. Сохранить проверки GCC и полные журналы
прямого результата, затем проверить разбор внутри пространства.

## Описание типов функций

Добавить функцию как отдельный вид типа. Описание содержит возвращаемый
тип, типы до восьми параметров, наличие прототипа и признак ... . Сначала
разбирать список параметров в отдельное описание прототипа, а функцию
с возвращаемым типом получать при обратном применении declarator. Имена
параметров не входят в совместимость типов; временные имена действуют
в оставшейся части списка. Имена типов и enum, введённые в прототипе,
не должны выходить в содержащую область. При этом сами описания типов
сохраняются для сравнения и последующего вызова.
Массив и функцию в параметрах преобразовать в указатель; верхние
квалификаторы параметров и возвращаемого типа не учитывать в совместимости.
Квалификаторы typedef функции игнорировать, как в проверенном GCC ILP32.
Пустой список () отличается от (void): первый не задаёт прототип.
Совместимость () с прототипом допускается, если нет ... и все параметры
сохраняют тип после продвижений. Проверять возвращаемый тип, параметры,
их количество и наличие ... . Для GNU sizeof/alignof функции использовать
один байт, массивы функций, функции с возвратом массива или функции
и функции как поля объектов отвергать.
На этом шаге проверить typedef функций, указатели и массивы таких
указателей, поля и параметры, sizeof/typeof и выбор по типу. Адреса
функций, объявления через полный declarator и косвенный вызов ещё
требуют следующей части ABI; не размещать функцию как объект данных.
Описание списка допускает ... , но его вызов ещё не объявлять реализованным.

## Адреса функций в ABI копирований

Для указателя на функцию использовать адрес описания функции в отдельной
таблице ABI. Таблица занимает байты 19456..20479, содержит 16 записей
по 64 байта и не отнимает место у глобальных объектов 12288..16383.
Запись содержит битовый адрес входа, смещения ячеек возврата и результата
от начала кадра, затем смещения до восьми параметров. Заполнять её после
разбора всего исходника. Тип указателя — обычное 32-битное значение C,
но функция не размещается как объект данных и её адрес не означает
разрешение читать служебную таблицу через произвольный указатель на данные.
Функция в выражении и разыменование указателя на функцию образуют
обозначение функции; получение значения преобразует его в указатель.
&функция возвращает тот же указатель. sizeof функции остаётся равен одному.
Прямые объявления и определения нынешнего разбора должны сохранять
описание типа функции, чтобы typeof, сравнение типов и _Generic видели
сигнатуру. Получение адреса требует определения функции к концу исходника;
невычисляемые операнды и невыбранный _Generic этого требования не создают.
Начать с адресов и постоянных инициализаторов, затем добавить косвенный
вызов: проверка адреса описания, однократное чтение указателя, передача
параметров в кадр по смещениям, переход на вход, возврат результата.
До реализации последней части косвенный вызов явно отклоняется.
Ни разбор C, ни выбор функции не выполняются хостом.

## Косвенный вызов в ABI копирований

Читать указатель на функцию один раз до разбора аргументов. Проверить
диапазон таблицы описаний и выравнивание записи 64 байта, затем проверить
ненулевой адрес входа. Читать поля описания копированиями: младшие девять
бит адреса поля фиксированы, старшие биты берутся из проверенного указателя.
Параметры преобразовать по прототипу и сохранить перед сменой кадра.
Смещения возврата, результата и параметров преобразовать в адреса нового
кадра до его выбора. Только адрес входа, адрес ячейки возврата и адреса
параметров временно хранить в служебных ячейках 154304..154623 бит;
после входа в функцию они не нужны. Указатель на результат сохранять
в кадре вызывающей функции, чтобы вложенный вызов не уничтожил его.
Записать адрес продолжения в новый кадр, перейти на вход, после возврата
восстановить кадр без временной записи в кадр завершённой функции и
прочитать результат через сохранённый указатель. Сохранить проверку
переполнения стека. Поддержать нынешние скаляры и указатели; агрегаты,
64-битные значения и вызов ... пока требуют расширения ABI.
Для main добавить отдельный начальный слой: он записывает адрес возврата
в исходный кадр, входит в main, затем направляет результат в OUT. Сам main
возвращается как обычная функция, поэтому прямой и косвенный вызовы main
не должны преждевременно завершать образ.
Проверить callback, рекурсию, вложенные вызовы, выбор разных функций,
ширины char/short, восемь параметров, main и отказ неверного адреса.
Сверить с GCC, сохранить полные прямые журналы и проверить компиляцию
примера косвенного вызова внутри пространства.

Байтовый тест нечётного адреса должен обращаться к свободной памяти,
а не менять ячейку возврата начального кадра. Для него принять адрес
2097137; другие проверки последнего байта и полуслова сохранить.
При проверке volatile-указателя после предварительного объявления
f(int) его объект в прежнем общем размещении располагался на смещении
160 бит исходного кадра. После отдельного размещения по функциям
первый объект main находится на смещении 64 бита.
Проверять число фактических 32-битных чтений этого адреса в полном журнале.

## Объём кода для косвенных вызовов

Четыре места косвенного вызова превысили прежние 128 слоёв кода.
Увеличить текущий предел до 384: код начинается с байта 32768 и
заканчивается до байта 905216, ниже кадров с байта 1048576.
Это увеличение вместимости нынешнего результата 2 МиБ, а не доказательство
достаточности памяти для Linux. Увеличенный буфер результата расширяет
словарь компилятора сверх прежних 2 МиБ: при подготовке принять ёмкость
4 МиБ и пул только компилятора 8 МиБ. Обычный pForth не менять. Проверить
сборку образа в нынешней гостевой памяти 16 МиБ и исполнение большого
примера вызовов; сохранить фактические размеры и контрольные суммы.

## Размещение кадра отдельно для каждой функции

При разборе каждой функции начинать виртуальные смещения с 131072 бит.
В начале кадра — 32-битный адрес возврата и 64-битное поле результата, далее параметры и
локальные объекты. Предел 2048 байт относится к одной функции, а не к
сумме всех разобранных функций. Кадры исполнения по-прежнему различаются
указателем текущего кадра и занимают верхний МиБ пространства.
Тип возвращаемого значения и типы параметров сохранять отдельно в
метаданных каждой функции: сведения об одном виртуальном смещении
при разборе другой функции могут измениться. Прямой вызов должен брать
типы из этих метаданных, проверять и преобразовывать аргументы через
временные описания, а записывать параметры по сохранённым адресам.
Нельзя менять описание объекта вызывающей функции для проверки параметра
вызываемой. Совместимость повторного объявления проверять по сохранённым
типам, после чего разбирать параметры и тело с новым размещением.
Сбрасывать временные описания lvalue, постоянных значений и происхождения
указателей перед новой функцией. Проверить разные типы на одинаковых
смещениях, предварительные объявления, рекурсию, указатели на локальные
объекты и две большие функции, чьи кадры отдельно помещаются в 2048 байт.
Это не расширяет общий объём пространства до достаточного для Linux.

## Общий разбор внешних объявлений функций

Функции и объекты внешнего уровня разбирать одним declarator. Вид
полученного типа определяет объявление функции либо объекта. Разрешить
скобки вокруг имени, typedef функции, несколько объявлений через запятую
и явный возврат указателя на функцию. Список параметров ближайший к имени
функции сохраняет область имён до разбора тела; вложенные прототипы
callback и возвращаемого указателя имеют собственную временную область.
Именованные и безымянные параметры размещать по их фактическому типу.
При обычном объявлении удалять временные имена параметров, enum и меток
типов. Тип функции проверять структурно с прежним объявлением; сохранять
более полный прототип и не менять адреса параметров уже определённого тела.
Определение через один typedef функции без списка параметров отклонять.

## Необходимые части

1. GNU C11: препроцессор с включаемыми файлами и макросами, полный набор
   типов и преобразований, указатели, агрегаты, инициализаторы, 64-битная
   арифметика, управление потоком, прототипы, глобальные объекты, функции
   с переменным числом параметров; GNU-расширения ядра, встроенные функции
   и атрибуты. Неизвестный атрибут с существенной семантикой нельзя молча
   пропускать. Полный hosted C и библиотека libc не требуются для ядра.
2. ABI копирований: размещение типов и данных, стек вызовов, адреса объектов,
   параметры, возвращаемые значения, рекурсия и косвенные вызовы. Указатель
   на локальный объект должен сохранять адрес при вызове другой функции.
3. Раздельная компиляция и линковка: секции, символы, перемещения, библиотечные
   операции, начальное размещение; вход включает все исходники и заголовки.
   Работа с файлами сборки выполняется внутри пространства, а не скрытым
   вызовом хостового GCC/Clang для пользовательского задания.
4. Порт Linux: архитектурные заголовки, начальный код, операции вместо
   встроенного ассемблера других архитектур, атомарные операции, обработка
   событий, таймер и консоль, договор загрузки и управления памятью.
5. Расширение адресации и памяти: нынешний прямой результат рассчитан на
   2 МиБ и поля 23/24/24. Конкретный больший объём следует выбирать по
   измерениям образов компилятора и ядра; достаточность 2 МиБ не доказана.

## Первое изменение: стек вызовов

Устранить статическое размещение локальных данных при исполнении.
Для текущих int-функций вводится фиксированный кадр вызова 2048 байт.
Компилятор назначает смещения слов в кадре; исполняемые копирования
подставляют адрес текущего кадра в поля доступа. Данные вызывающей функции
остаются на месте. Это даёт основу для последующего адреса локального
объекта, в отличие от сохранения статических областей и их восстановления.

Кадры располагаются в верхнем МиБ пространства, растут от битового адреса
8388608 с шагом 16384 бита. Доступны 512 кадров, включая main. Указатель
кадра хранится в служебной области; адрес возврата находится в кадре.
Перед вызовом аргументы временно сохраняются вне кадров, проверяется
граница, выбирается следующий кадр, записываются параметры и адрес возврата.
При возврате результат временно сохраняется, выбирается прежний кадр.
Непосредственная рекурсия разрешается. Вызовы main, неизвестных функций
пока по-прежнему отвергаются.
Переполнение даёт `copy-c: stack overflow` с переводом строки и idle,
без выхода за пределы пространства. Это не реализация всего ABI Linux.

## Прототипы и взаимная рекурсия

Поддержать предварительные объявления int/int*-функций с int/int*-параметрами,
включая параметры без имён. Определение должно совпадать с объявленным
числом параметров; при определении имена обязательны. Повторные одинаковые
объявления разрешаются, повторное определение отвергается. Адреса прямых
вызовов объявленных функций заполняются после определения; вызванная,
но не определённая функция даёт ошибку до выдачи пакета. Неиспользуемый
прототип разрешается. Это даёт взаимную рекурсию в одном исходном файле;
раздельная компиляция и внешние функции ещё не реализованы.

## Адреса локальных объектов

Следующий проверяемый объём ABI — `int *`, получение адреса `&local`,
чтение и запись через `*pointer`, передача указателя и возврат указателя.
Значение указателя — обычный байтовый адрес объекта в пространстве.
При обращении копирования превращают его в битовый адрес, сдвигая на три
разряда. `pointer + int` масштабируется на sizeof(int), то есть четыре байта;
разность указателей делится на четыре. Это представление пригодно для
последующего побайтового доступа и не меняет размер sizeof(int).

Пока допустимы только выровненные int-объекты в верхнем МиБ кадров.
Другие диапазоны и NULL при разыменовании завершаются сообщением
`copy-c: pointer error` и idle. Такая проверка защищает код и служебные
области от записи, но ещё не обнаруживает указатель на завершённый вызов
и выход за границы отдельного объекта. Как и в C, они не становятся
разрешёнными операциями. Поддержка int* не означает поддержку char*,
массивов, всех квалификаторов и всех типов C. Вызовы через указатели
функций остаются отдельной частью ABI.

## Целочисленная семантика перед дальнейшим переносом GNU C

Исправить различие `int` и `unsigned int`: оба имеют 32 разряда,
но сравнения и правый сдвиг используют знаковость. При смешивании этих
типов результат арифметики становится unsigned; присваивание сохраняет
младшие 32 разряда. Для литералов поддержать основания 2/8/10/16 и суффикс
U. Несуффиксный hex/octal/binary, превышающий INT_MAX, имеет тип unsigned;
десятичный литерал, требующий 64-битного типа, пока явно отвергать.

Добавить битовые операции, сдвиги, целочисленное умножение, деление и
остаток, логические операции с коротким замыканием и условное выражение.
Арифметика результата должна исполняться копированиями. Обработка знака
деления выполняется перед и после общего беззнакового алгоритма; деление
на ноль и недопустимый размер сдвига завершаются диагностикой через OUT.
Это проверяемая часть необходимых изменений; она ещё не означает поддержку
всего GNU C или сборку Linux. Существующая семантика переполнения signed
остаётся явно описанным расширением подмножества, а не обещанием GNU C.

Увеличить предел результата до 128 слоёв и перенести контроль загрузки
за всю зарезервированную область кода: данные в бит 7340032,
код в бит 7372800.
Вместимость образа самого компилятора в 512 КиБ проверить сборкой,
а не предположить.
Для подготовки этого словаря выделить 384 КиБ кода и 64 КиБ имён;
в готовом образе компилятора оставить 8 КиБ резерва кода и 4 КиБ имён,
поскольку пользовательский C не добавляет определения Forth.
Обычный образ pForth сохраняет прежние размеры и резервы.

Полноценный фронтенд GCC требует также его среды выполнения внутри
пространства. TinyCC рассматривается как более компактный исходник для
переноса, но его совместимость с Linux 6.12 не установлена. Хостовый GCC
может использоваться только как эталон в тестах, не в производственном
разборе пользовательского C.

В проверках сопоставлять SHA-256 текущего Forth-исходника с метаданными
подготовленного словаря и гостевого образа до исполнения. Сохранённый
сырой журнал должен описывать именно этот исходник, а не устаревший образ.

## Следующее расширение разбора C

Ввести метаданные lvalue для локальных объектов и разыменования int*.
Присваивание становится выражением с правой ассоциативностью; результат
имеет тип назначения и не является lvalue. Запись через указатель
вычисляет адрес назначения до правого операнда и сохраняет его отдельно,
поэтому изменение самой переменной-указателя в правом операнде не меняет
уже вычисленный адрес. Использовать этот же путь для составных присваиваний
и префиксного/постфиксного ++/--. Возврат постфиксного выражения сохраняет
предыдущее значение, префиксного — новое. Унарный + выдаёт rvalue.

Добавить оператор запятой с выполнением слева направо. Аргументы вызова
и инициализаторы отдельных объявлений разбираются как выражения
присваивания, чтобы запятая-разделитель не превратилась в оператор.
Внутри скобок, операторов управления и return доступны полные выражения.
Поддержать несколько объявлений одного типа, разделённых запятой.

Добавить for и do/while, break и continue. Для каждого разбираемого цикла
сохранить собственные неразрешённые переходы; внутренний цикл разрешает
только свои переходы. Continue переходит к проверке while, к проверке
do/while либо к изменению for. Объявление в инициализаторе for видно
до конца этого цикла. Проверять вывод, завершение и состояние копированиями.

Далее вводятся область видимости блока с затенением, sizeof, typeof
и GNU-выражения из операторов. Невычисляемые операнды должны проверяться
по типам, но не выдавать исполняемые копирования и не создавать зависимость
от определения функции. Во всём этом этапе действуют нынешние типы
int/unsigned int/int*; добавление синтаксиса не заменяет работу с остальными
типами GNU C, препроцессором, линковкой и портом Linux.

Для невычисляемых операндов отключать генерацию инструкций, сохраняя
разбор и проверки типов. После разбора восстанавливать счётчики временных
данных, констант и вызовов и очищать их метаданные. Это предотвращает
изменение уже сформированного кода и накопление неисполняемых вызовов.
GNU-выражение с последним оператором, не являющимся выражением, имеет
тип void; его можно отбросить, но нельзя использовать в арифметике или
присваивании. Для него GNU sizeof возвращает 1. Функции с возвращаемым
типом void и прочие широкие типы реализуются отдельно.

Расширение цепочки разбора выражений выявило переполнение стандартного
стека возвратов pForth (512 ячеек) раньше проверки глубины C. Только в
готовом образе C-компилятора создавать задачу pForth с 2048 ячейками
возвратов после инициализации словаря. Обычный pForth и подготовка словаря
сохраняют прежнюю задачу. Проверить допустимую глубину и отказ при
превышении, без падения процесса.

не удаляются и не заменяются сводкой. Прежнее gzip-сжатие доступно.

32768 токенов определений, 64 уровня раскрытия, 256 КиБ текста склеек,

## Скалярные описания типов и объекты

Добавить локальный __auto_type для нынешних скаляров и указателей:
один простой идентификатор с обязательным начальным выражением.
Выводить тип после преобразования массива/функции в указатель и удалять
верхний const/volatile. Не выполнять целочисленное продвижение сверх

Сохранять отдельные описания int, unsigned int, char, signed char,
unsigned char, short, unsigned short, long, unsigned long, _Bool и void.
Размеры, выравнивания и ранги задаются выбранным ILP32 ABI; char знаковый, но отличается
по типу от signed char. Указатели образуются из описания типа объекта,
включая void* и указатель на указатель. Квалификаторы и 64-битные значения
остаются следующими частями полной системы типов.

Объекты char/_Bool занимают один логический байт, short — два; временные
скалярные значения занимают четыре. Метаданные кадра адресуются по байту,
чтобы соседние маленькие объекты не разделяли одну запись. Чтение и запись
меняют только ширину объекта; знаковое расширение, усечение и нормализация
_Bool выполняются копированиями. Перед арифметикой char/short/_Bool
продвигаются в int. int и long имеют равный размер, но разные ранги.
Смешивание unsigned int и long даёт unsigned long. sizeof/typeof не
продвигают операнд. _Alignof и GNU __alignof/__alignof__ не исполняют
операнд и используют выравнивание описания. GNU sizeof/alignof(void) равны одному.

Разыменование проверяет диапазон и выравнивание по типу объекта.
unsigned char* может читать и менять логические байты int, не затрагивая
соседние байты. Шаг указателя и разность берутся из размера объекта;
GNU void*-арифметика использует шаг один, разыменование void запрещено.
Неявно совместимы одинаковые указатели и переход через void*; несвязанные
типы указателей отвергать. Явное приведение между указателями допускается.
Прототипы различают типы даже при равных размерах. Параметры и возвращаемые
значения приводятся к объявленному типу. Добавить функции void и return;
в non-void-функции пустой return отвергать, main сохраняет тип int.

## Упаковка полей в гостевом C-runtime

Сквозное исполнение новой системы типов показывает высокую цену cc-bits!,
которое упаковывает каждое поле через интерпретируемые слова Forth.
Добавить CS-PUT-BITS только в сборку C-компилятора: пять аргументов —
значение, ширина, битовая позиция, адрес буфера и адрес таблицы обращения
битов байта. Это запись битов в память гостя; разбор C, типы, размещение
и выбор копирований остаются в Forth. C-функция включается в загруженный
RV32I-образ и исполняется копированиями внутри пространства. Ядро
эмулятора не изменять. Обычный pForth не получает нового слова.

Упаковывать до восьми бит за итерацию, сохраняя остальные биты байта.
Ширины и позиции задаёт существующий генератор Forth. Сравнить все
пакеты и ошибки с сохранённым прежним compiler32 побайтно; затем
исполнить новый компилятор внутри пространства с полным сырым журналом.
Учитывать SHA-256 custom.c при кешировании словаря: общие слои и загрузчик
подготавливаются этим же примитивом, и изменение C-функции требует
повторной подготовки словаря.

## Постоянные выражения и размеры агрегатов

Перед массивами расширить размер и выравнивание в описаниях типов до
32-битных ячеек; байтовый размер не вместит даже массив из 256 char.
Временные значения получают отдельный признак целочисленного постоянного
выражения и его значение. Литералы, sizeof/alignof, допустимые приведения
и операции над постоянными операндами вычисляются компилятором внутри
пространства. Не считать значение локальной переменной постоянным из-за
инициализации литералом; присваивание и вызов в исполняемой части не
становятся постоянными выражениями. Учитывать короткое замыкание &&/||/?:
и не вычислять деление на ноль в неисполняемом операнде.

Разбор размера массива использует этот же разбор C в неисполняемом режиме,
проверяет целочисленный тип, постоянность, положительную длину и
переполнение произведения размера элемента на длину. Динамические массивы
реализуются отдельно. Эти значения также нужны _Static_assert, enum,
offsetof и глобальным инициализаторам; не переносить вычисление на хост.
Сопоставить значения и отказы с GCC ILP32, сохранить прямые журналы и
сквозную компиляцию нового разбора внутри пространства.

Для локальных массивов хранить объявленный тип без преобразования к
указателю; sizeof и typeof видят весь массив. В обычном выражении массив
преобразуется в указатель на первый элемент. &array образует указатель
на весь массив. Для вложенных массивов сохранять порядок измерений.
Индекс вычисляется один раз; адрес элемента — адрес начала плюс индекс,
умноженный на размер элемента. Массив целиком не является присваиваемым.
Элементы обозначаются отдельными временными lvalue через указатель,
чтобы метаданные первого элемента не перезаписали тип всего массива.
Адрес разыменованного объекта не требует чтения его значения; &*p не
должно разыменовывать NULL. Нулевую и явную инициализацию, включая
незаполненный хвост, выполнять копированиями внутри пространства.

## Требования из заголовков выбранного ядра

Для обычных строк использовать тот же декодер байтов, объединять соседние
литералы через пробелы и комментарии и добавлять завершающий NUL.
Размещать массивы char со статическим временем жизни в отдельной области
байтов 12288..16383; её содержимое входит в загружаемый пакет. Область
не пересекается с idle-кодом, кадрами, константами и таблицами. Начало
образа переносится на бит 98304, начало виртуальных кадров остаётся
131072. Проверка указателя разрешает эту область и верхний МиБ кадров,
но не служебные данные между ними. Это ограничение текущего ABI;
для Linux потребуется увеличить размещение объектов и размер пространства.
Строковое выражение сохраняет тип массива char и доступно через
существующее разыменование. Запись в строковый литерал имеет неопределённое
поведение C; отдельного запрета на неё пока не вводить.
Инициализатор массива char/signed char/unsigned char копирует байты
литерала, допускает ровно достаточный размер без завершающего NUL и
обнуляет остаток большего массива. Эти же правила применяются к полям
структур и вложенным массивам; слишком короткий массив отвергается.
Для char s[]="..." размер выводится из декодированного литерала, включая
NUL. Определение размера не должно создавать копирований или второй
строковый объект; чтение инициализатора повторяется после размещения s.

Начать глобальное размещение с целых объектов естественного выравнивания.
Они разделяют статическую область со строками, имеют отдельные сведения
о типах и обычные имена уровня файла. Имена видны во всех последующих
функциях и могут быть скрыты локальными именами. Начальное значение —
нулевое либо целое постоянное выражение с преобразованием к типу объекта;
для скалярного начального значения допускаются фигурные скобки.
оно записывается в образ компилятором внутри пространства, а не отдельной
процедурой хоста или кодом перед main. const/volatile сохраняются.
Для повторных скалярных объявлений объединять совместимые типы и
сохранять одно размещение. Различать extern-объявление, предварительное
определение без инициализатора и определение с начальным значением.
Последнее допустимо только один раз. extern без определения допустим,
если объект не используется при исполнении; sizeof и невыбранные
ассоциации _Generic не создают требования к определению. Для этого
сохранять список обращений, а при исключении раннего default _Generic
удалять из него соответствующий участок вместе со списком вызовов.
В конце единицы компиляции отвергать обращение к неопределённому extern.
Линковка разных файлов и глобальные агрегаты ещё требуют реализации.
Для глобального указателя принимать NULL, адрес статического объекта
или строки и постоянное смещение такого адреса. Учитывать совместимость
типов и квалификаторы через существующую проверку присваивания. Чтение
значения другого глобального указателя не является адресной константой.
Разбирать начальное значение без исполнения копирований; сведения о
постоянном адресе хранить отдельно от содержимого объекта. Обращение к
extern в адресном начальном значении требует определения, а sizeof
внутри него такого требования не создаёт. Во время разбора начального
значения временно разрешить запись обращений на текущем уровне подавления
исполнения; вложенные неисполняемые операнды остаются исключёнными.
static уровня файла задаёт внутреннее связывание объекта или функции.
extern после static сохраняет внутреннее связывание; static после
внешнего объявления отвергается. Для объектов объявление без класса
после static конфликтует; для функции оно наследует предыдущее связывание,
как extern. Сохранять связывание в сведениях компилятора для последующего
экспорта линкеру. Локальные static пока требуют отдельного размещения
и постоянных сведений, не исчезающих при выходе из области имён.

Следующее расширение: локальное объявление с ведущим static размещает
объект в общей постоянной области с выравниванием его типа. Начальное
значение записывается в пакет при компиляции внутри пространства,
без исполнения при входе в функцию. Без начального значения байты
нулевые. Имя имеет обычную область видимости блока, а адрес и содержимое
сохраняются между вызовами и при рекурсии. Для скаляров и агрегатов
использовать прежнюю проверку постоянства и разбор инициализаторов,
включая long long, строки, вывод размера массива и назначенные значения.
Указатели на локальный static допускаются как постоянные адреса;
адрес автоматического объекта в таком инициализаторе отвергается.
Пока этот шаг не вводит локальные extern и произвольное расположение
класса хранения среди спецификаторов. Они остаются частью полного GNU C.

Размещение глобальных объектов расширить на полные массивы, структуры
и объединения. Применять те же правила последовательных и вложенных
инициализаторов, что для локальных объектов, но записывать постоянные
значения в образ во время разбора внутри пространства. Не генерировать
процедуру начальной загрузки перед main. Неинициализированные байты и
padding обнулять. Для char[] со строкой выводить размер из литерала.
Проверять постоянство каждого скалярного значения и известность адреса
назначения; присваивания и увеличение объектов внутри начального
выражения отвергать. Адреса полей и элементов сохранять как постоянные
сведения независимо от содержимого объектов. Неполные extern-массивы,
designated-инициализаторы и копирование агрегата целиком ещё требуют
отдельной реализации; не подменять неизвестный размер произвольным запасом.
Добавить назначенные инициализаторы одного уровня для глобальных и
локальных объектов: .поле=значение и [индекс]=значение. Следующий обычный
инициализатор продолжает после указанного поля или элемента. Проверять
существование поля и границы индекса. Повторное назначение обновляет
объект; перед повторной инициализацией агрегата обнулять весь выбранный
подобъект, а перед выбором члена union — всё объединение. Цепочки
designators (.поле[индекс].поле) пока явно отвергать: их продолжение
требует обхода оставшихся подобъектов, а не только увеличения внешнего
индекса. Эти цепочки и диапазоны GNU остаются частью общей цели.
Продолжить цепочки рекурсивным входом в выбранный подобъект без скобок:
после последнего назначения заполнять оставшиеся элементы его контейнера,
затем продолжать внешний контейнер. Новый designator после запятой
относится к ближайшим явным скобкам. При входе по цепочке не обнулять
весь выбранный агрегат, иначе повторная цепочка уничтожит соседние поля.
Для union сохранять активный член по происхождению адреса подобъекта;
при смене члена обнулять всё объединение, при продолжении того же члена
сохранять уже заданные поля. Обнуление агрегата сбрасывает сведения о
union внутри него. Происхождение локального указателя хранить отдельно
от постоянного значения C, чтобы не разрешить адрес кадра в статическом
начальном значении. Ограничивать глубину рекурсивного разбора существующим
ограничением вложенности.

Размер массива [] из списка определять отдельным разбором тем же
инициализатором с подавленным исполнением и без записи объектов.
Считать наибольший выбранный внешний индекс плюс один; учитывать
продолжение после цепочек и пропуск скобок. Не подставлять произвольную
верхнюю границу массива. Сохранить и восстановить все сведения о типах,
именах и union, поскольку sizeof/typeof в выражении могут определять
новые типы. Снимок временно размещать в памяти компилятора и освобождать.
Пул pForth для компилятора увеличить с 64 КиБ до 4 МиБ: текущий снимок
сведений занимает больше 64 КиБ. Изменение относится только к образу
компилятора; обычный pForth и эмулятор пространства не расширяются.
При измерении имя самого массива видно с неполным типом. При настоящей
инициализации использовать временное представление с тем же неполным
типом, привязанное к уже размещённому объекту, и завершить тип после
инициализатора. Это сохраняет смысл sizeof и проверки совместимости
типов внутри собственного инициализатора. Проверять совместимый ранее
объявленный полный тип перед выводом размера глобального массива.
Пустые списки GNU и неполные extern-массивы пока требуют отдельного
размещения; не выделять им фиктивный объект размером в один элемент.
Добавить токен ... и диапазоны [первый ... последний] = значение по
[правилам GCC](https://gcc.gnu.org/onlinedocs/gcc/Designated-Inits.html).
Проверять порядок и границы до умножения; для [] учитывать последний
индекс плюс один. Скалярное значение сохранять до заполнения элементов,
чтобы не повторять вызов, n++ или чтение volatile. Локальный агрегат
сначала инициализировать в отдельном временном объекте, затем копировать
его целиком в выбранные элементы. Глобальный агрегат допускает разбор
в первый выбранный элемент и копирование постоянных байтов в остальные.
Копировать сведения о выбранных членах вложенных union вместе с объектом,
чтобы последующая цепочка не уничтожала его поля.
Расширить диапазоны на цепочки полей и индексов, включая несколько
диапазонов в одной цепочке. Сохранить путь выбранных подобъектов,
вычислить значение один раз и обойти все сочетания индексов. Копировать
только конечный подобъект, сохраняя соседние поля. Для union выбирать
член до записи и восстанавливать сведения о нём после копирования.
После заполнения продолжать с конечного подобъекта при наибольших
индексах: сначала оставшиеся поля/элементы внутреннего контейнера,
затем внешних. При выводе размера [] достаточно разобрать значение
и проверить верхние границы, без повторного обхода всех сочетаний.
Хранить путь отдельно для каждого вложенного разбора, поскольку
выражение значения может содержать GNU-блок с другим инициализатором.

Для обычных символьных литералов декодировать стандартные escape,
восьмеричные до трёх цифр и hex escape внутри пространства. Константа
имеет int; один байт расширяется со знаком char, несколько байтов GNU
складываются слева направо с сохранением последних 32 бит. Backslash
перед переводом строки не создаёт байт. Пустая константа, незакрытая
кавычка и пустой hex escape — ошибка. Общий декодер использовать затем
для строк и инициализаторов; широкие и универсальные символы пока
остаются отдельной незавершённой работой.

Для enum хранить отдельное описание типа и его совместимый целый тип.
В проверенном GCC ILP32 неотрицательный enum совместим с unsigned int,
а содержащий отрицательное значение — с int; разные enum несовместимы.
Константа, помещающаяся в int, имеет int; большая 32-битная константа GNU
имеет тип своего enum. Имена констант используют то же обычное пространство
имён и восстановление видимости, что typedef и объекты. Начальное значение
равно нулю, следующее увеличивается на единицу. Проверять постоянный
инициализатор; неявный переход через INT_MAX отклоняется, как в GCC.
Проверять повтор имени, незавершённый тип и диапазон. Диапазон,
требующий 64 бит, реализовать вместе с расширением целых; пока отклонять
его явно. _Generic должен отдельно отклонять несколько подходящих
ассоциаций, поскольку совместимость enum с целым типом нетранзитивна.

Следующий шаг объявлений — typedef. Имя хранит уже разобранный тип,
не создавая новый несовместимый тип. Применять квалификацию к исходному
типу псевдонима, включая массив и указатель. Для имён typedef действует
обычное пространство имён C вместе с объектами и функциями; метки
структур остаются отдельными. Разрешить скрытие внешнего typedef
локальным объектом и скрытие внешнего объекта локальным typedef,
отклонять конфликт в одной области. Восстанавливать видимость при
выходе из блока, функции и for. Проверить одинаковое повторное объявление,
несовместимое повторное объявление, массивные псевдонимы и параметры.

После размещения агрегатов реализовать `__builtin_offsetof` для полей
и постоянных индексов массивов, `__builtin_types_compatible_p` для
нынешних типов и `_Static_assert`. Смещение и сравнение типов возвращают
целочисленное постоянное значение из описаний типов; не читают объект.
При статическом утверждении не исполнять его операнд и не выдавать
часть двоичного пакета при ошибке. Пока квалификаторы, enum и typedef
не реализованы, сравнение типов не объявлять полной семантикой GNU C.
Вычисляемый индекс offsetof требует отдельного изменения после
постоянных индексов. `_Generic` и настоящий заголовок container_of
остаются обязательными незавершёнными проверками следующего этапа.

Для `_Generic` проверить все типы и выражения, но исполнять только
выбранное выражение. Сохранить его lvalue и постоянное значение.
Управляющий операнд разобрать без исполнения, с преобразованием массива
в указатель. Default допустим в любой позиции: если он разобран до
подходящего типа, его код разместить за обходящим переходом и исключить
его неиспользуемые вызовы из проверки определений при завершении.
Не разбирать выбранное выражение повторно: это повторяло бы объявления
меток внутри typeof/sizeof. Два совместимых типа либо два default — ошибка.
Ассоциации ограничены нынешними полными объектными типами.

Проверка исходного архива 6.12 показывает следующую цепочку для
`include/linux/container_of.h`: GNU-выражение, void*, обращение к полю,
offsetof, typeof, __builtin_types_compatible_p и _Static_assert. Вариант
с сохранением const использует _Generic. Одного разбора typeof и GNU-блока
для этого недостаточно. Первой проверкой агрегатов должен стать именно
такой полный пример с проверкой типа и восстановления адреса объекта.

`include/linux/types.h` требует typedef, _Bool, char/short/long и 64-битных
целых. `include/linux/compiler_types.h` также использует _Generic для
снятия квалификаторов скалярного типа. Сравнение типов должно различать
char и signed char, int и long, даже при равных размерах.

`include/linux/compiler_attributes.h` задаёт, среди прочего, alias,
aligned, packed, section, cleanup и gnu_inline. Для cleanup требуется
вызов при выходе из области видимости; для alias и section — поддержка
линковки. Эти атрибуты нельзя принимать как пустые слова. Проверять
активные ветви после препроцессора для выбранной конфигурации; наличие
атрибута в заголовке само по себе ещё не означает его использование
в минимальном ядре. Постоянные выражения для _Static_assert, размеров
массивов и offsetof вычисляются компилятором внутри пространства.

## Расширение памяти среды компилятора

Следующий шаг типов — const и volatile. Описания квалифицированных
типов должны ссылаться на исходное описание: завершение предварительной
метки структуры обновляет размер и выравнивание и для квалифицированного
типа. Продвижение и получение скалярного значения снимают только внешние
квалификаторы, сохраняя квалификаторы типа за указателем. Доступ к полю
const/volatile структуры наследует их; для поля-массива квалифицируется
элемент. Запрет записи в const проверять при присваивании, но разрешать
инициализацию и заполнение параметров вызова.

Встроенное сравнение типов снимает внешние квалификаторы. Для _Generic
использовать отдельное сравнение: управляющее выражение проходит
преобразование lvalue, а квалифицированные ассоциации остаются разными.
Присваивание указателя разрешает добавить квалификаторы одного уровня,
но запрещает их снятие и небезопасное преобразование int** в const int**.
Составное присваивание, ++/-- и запись в поле тоже проверяют const.
Выражение с отбрасываемым volatile-значением должно выполнять чтение
копированиями; sizeof/typeof/_Generic не исполняют управляющий операнд.
Restrict и _Atomic не принимать без отдельной реализации их правил.

Запись через volatile-указатель не должна предварительно читать объект,
а postfix ++/-- должен читать его ровно один раз. Для этого разыменование
создаёт описание lvalue с сохранённым адресом; чтение откладывается до
получения значения, а присваивание использует адрес непосредственно.
Void-разыменование GNU создаёт void-выражение без чтения памяти, что
нужно для typeof(*ptr) в container_of. Проверки volatile сверять с
[правилами GCC](https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html) и числом
реальных чтений в журналах копирований, включая присваивание через
указатель, postfix ++ и последний операнд GNU-блока.


Решение: отдельная сборка того же эмулятора на 64 МиБ
(`space-64m`), без новых операций со стороны хоста. Поля копирований
28/29/29, слой 22016 бит. Сохраняется обычная сборка на 2 МиБ.
Размещение RV32I задаётся для каждого образа, без изменения глобальных
констант, влияющего на другие одновременно подготавливаемые образы.

Гостевую память размещать с половины пространства; загрузчик, его
константы и таблицы — с трёх четвертей. Для 64 МиБ выделить 16 МиБ гостю.
Допускать только степени двух от 64 КиБ до четверти пространства:
полная передача этого объёма помещается в поля длины и статуса канала.
Выводить из размещения поля адресов, слой, установочную запись стандартного
core и размер её литерала. Установочная запись включает дополнительный
байт, который уже проверяется core. Не менять договор core.

Образ C-компилятора перевести на эту среду, увеличить буфер исходника
до 1 МиБ, ёмкость подготовки словаря до 2 МиБ кода и 64 КиБ имён,
пул подготовки до 4 МиБ. Словарь обычного pForth не менять.
Вместимость каждого готового образа проверяется линкером относительно
выбранного стека. Это запас для следующих частей GNU C; достаточность
16 МиБ для сборки всего ядра не утверждается.

Прямой результат нынешнего C-компилятора по-прежнему имеет ABI 2 МиБ.
В сквозном тесте первый запуск использует space-64m, второй — обычный
space. Впоследствии расширить и прямое размещение и линковку ядра.
Проверить загрузку полного гостевого объёма, высокие адреса, границы,
IN/OUT, отвергнутые размеры, несколько размещений в одном процессе
подготовки и неизменность двоичного образа прежнего размещения.
Сохранить сырые журналы всех исполнений и новую сквозную компиляцию C.

Первый сквозной запуск исходника 8255 байт прерван пределом времени 3600 с
до выдачи пакета. Журнал содержит успешное чтение 66040 бит исходника;
это ещё не доказательство завершения компиляции. Для длительных проверок
добавить разбиение исполнения на части существующими --ticks/--dump-space,
продолжение через --core полного дампа и отдельные полные журналы частей.
Позиции IN/OUT учитывать по фактическим событиям каналов, поскольку stdio
может читать вперёд. Между запусками возвращать IN к логической позиции;
накапливать OUT без повторных байтов. Не разбирать C и не исполнять
RV32I на хосте. Проверить продолжение на независимом коротком примере
с остановкой во время загрузки и работы; сравнить конечную память и OUT
с непрерывным запуском. Лимит времени отдельной части задавать явно.

Продолжение проверки из уже сохранённых частей разрешать явно через
--resume-segments. До продолжения сверять SHA-256 исходного потока IN,
эмулятора и первоначального core, параметры размещения и длину OUT;
проверять SHA-256 восстановленного дампа. Сохранять прежние журналы частей.
Повторный запуск без этого флага не должен перезаписывать доказательства.
Проверить отдельный случай: остановить управление после полной части,
запустить продолжение заново и сравнить всю память/OUT с непрерывным
исполнением. Незавершённую часть не принимать за контрольную точку.

Решение для подстановки параметров: принимать отдельно исходные и
предварительно раскрытые токены каждого аргумента. Обычная подстановка
использует раскрытые токены, # использует исходное написание, ## использует
исходные токены. Пустой аргумент у ## сохраняется до завершения цепочки
склеивания, затем удаляется. Не принимать неверное склеивание или выход
за ёмкость результата. Повторное раскрытие и GNU-удаление запятой для
пропущенного переменного аргумента остаются отдельными обязательными этапами.

GCC принимает последовательности a####b и a## ##b и получает склеивание
крайних аргументов. Учесть это в подстановке, не отклоняя повторный ##
внутри тела. ## в начале и конце по-прежнему отклоняется. Первое сравнение
набора подстановки обнаружило эту границу; случай 17 проверяет исправление.

аргумент #, пустые аргументы ##, несколько токенов в аргументе, цепочки

Решение для повторного раскрытия: хранить неизменяемые наборы запретов
раскрытия токена, представленные битами индексов макросов. Одинаковые
наборы получают общий индекс через таблицу поиска. Поддержать добавление
имени, объединение и пересечение наборов; пересечение требуется для ##
и для границ вызова макроса. Исчерпание хранения означает явный отказ,
а не снятие запрета и повторное раскрытие. Сначала проверить операции
наборов отдельно, затем соединить их с последовательностью токенов.

```sh
  --file include/value.h=value.h -I include -o /media/user/data/work/job.in
```

--file передаёт явно перечисленные файлы без просмотра директив C.
-I задаёт каталог внутри набора, а не каталог файловой системы хоста.
При отсутствии -I набор использует корень имён. Обычный текстовый
вход без новых параметров сохраняет прежний формат. В metadata
сохранены SHA-256 исходных файлов и действительные смещения их байтов.
Пределы: 1024 файла, 32 каталога, имена до 4096 байт, стек 64 включения,
весь вход пока до 1 МиБ. Это ещё не вместимость для сборки Linux.
