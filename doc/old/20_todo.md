## C) “Толстые” throughput бенчи и оптимизации копий
- packing/permutation бенчи (copies×chunk sweep, CSV)
- оптимизации: fusion, DCE, copy propagation, alignment.

- **Layer scheduler (vertex-disjoint / unique-index-per-layer): fanout elimination via replication trees (telephone broadcast model)**
  - Контракт слоя/такта (строгий, аппаратно-реалистичный): в одном слое каждый индекс пространства может участвовать не более 1 раза (ни как `src`, ни как `dst`).
    - Эквивалентно для 1-битных копий: слой = набор попарно непересекающихся рёбер `src→dst` (vertex-disjoint matching).
    - Для интервалов: `src`-интервалы disjoint, `dst`-интервалы disjoint, и обычно `src∩dst=∅` внутри слоя.
  - Проблема: broadcast (1 источник → K получателей) при запрете fanout требует K слоёв, если делать “в лоб”.
  - Оптимизация: строить **дерево репликации** (использовать уже созданные копии как новые источники в следующих слоях), уменьшая глубину до:
    - `L_min = ceil(log2(K+1))` слоёв (нижняя граница достижима).
  - Пример (K=3):
    - слой1: `a→b`
    - слой2: `a→c` и `b→d` (в слое индексы не пересекаются)
  - Практическая задача: автоматическая перестройка и упаковка в слои:
    - детект fanout-групп (один `src` нужен многим `dst`);
    - выбор relay-узлов/буферов;
    - генерация replication tree;
    - упаковка рёбер по слоям как задача максимального matching при vertex-disjoint ограничении.
- Unified bench CSV schema + harness (для всех bench-скриптов)

## D) Дизайн устройств и каналов (новый фиксированный дизайн)
См. `doc/40_devices_channels.md`.

Цели:
1) Отделить понятие device от channel:
- device = self-describing object (device_id, type, ports)
- channel = порт устройства (endpoint) с протоколом

2) Менеджер устройств/каналов:
- выделить отдельную логику (страницы/слова), которая маршрутизирует каналы и выполняет цензуру
- обеспечить location transparency: внешнее/внутреннее устройство обслуживается одинаково

3) Набор базовых устройств:
- terminal device (stdin/stdout/stderr) как device object (а не 3 разрозненных канала)
- guest-space device (вложенное пространство как устройство)

4) Zero-copy соглашения:
- передача указателей/прав (capability/grant) вместо копирования payload.
