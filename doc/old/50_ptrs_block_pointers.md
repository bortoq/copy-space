# doc/50_ptrs_block_pointers.md — todo B: 2b pointers (Block pointers) ABI/семантика — 2026-05-05

## 1. Цель
Зафиксировать минимальный и быстрый контракт указателей (2b) для std7_fixed baseline:
- pointer-based слова (`*_P`) работают с **block pointers**,
- произвольные “raw bit pointers” (невыровненные bitaddr) откладываются на отдельный этап.

Цель этапа todo B: сделать пригодными `AP/BP/RP` для 24-bit данных без адресной арифметики.

## 2. Определения
- `bitaddr`: битовый адрес в `space` (как в VM).
- `ADDR_BITS`: ширина адреса (обычно 24), адрес хранится как беззнаковое число.
- **Block pointer**: `bitaddr`, удовлетворяющий выравниванию на 32 бита (см. ниже). Используется как база “ячейки” размера 32 бита.

## 3. Переменные указателей
В `space` существуют переменные:
- `VAR_AP`, `VAR_BP`, `VAR_RP` — содержат `bitaddr` (ширина = `ADDR_BITS`).

### 3.1 Alignment contract (обязательный для Block pointers)
Для block pointers требуется:

- `AP % 32 == 0`
- `BP % 32 == 0`
- `RP % 32 == 0`

То есть младшие 5 бит адреса равны 0 (low5=0).

## 4. Размещение 24-bit значения в block (ячейке)
24-bit значение хранится в 32-bit block по адресу `P` (block pointer):

- data bits: `[P + 0 .. P + 23]` (24 бита)
- padding/reserved: `[P + 24 .. P + 31]` (8 бит, зарезервировано)

Семантика “что означает порядок бит” — ровно та же, что уже используется существующими 24-bit словами `ADD24/EQ24/LT24` над `VAR_A24/VAR_B24/...`. Pointer-слова делают **сырой перенос 24 бит** без преобразований.

## 5. OFFTAB и невыровненная адресация
`OFFTAB` (таблица 5-bit оффсетов) используется существующим `EQ24P` для выбора бита внутри 32-bit блока путём патча low5 части адреса в src-field.

На этапе block pointers:
- для 24-bit load/store оффсет внутри блока считается фиксированным (0),
- произвольная невыровненная адресация “raw bit pointers” откладывается.

## 6. Слова todo B (минимальный набор)
### 6.1 Уже есть (baseline)
- `LITAP`, `LITBP`, `LITRP` — записывают адрес (bitaddr) в `VAR_AP/BP/RP`.

### 6.2 Добавить (block-pointer primitives)
- `LOAD24AP`: копирует 24 бита из `*AP` в `VAR_A24`
- `LOAD24BP`: копирует 24 бита из `*BP` в `VAR_B24`
- `STORE24RP`: копирует 24 бита из `VAR_SUM24` в `*RP`

Эти слова обязаны предполагать `AP/BP/RP` как block pointers (low5=0).

### 6.3 Производные (композиции / будущие convenience)
- `ADD24P` = `LOAD24AP; LOAD24BP; ADD24; STORE24RP`
- `LT24P`  = `LOAD24AP; LOAD24BP; LT24`

На первом этапе допускается реализовать `ADD24P/LT24P` как токен-макрос/последовательность токенов, не как отдельные слова (чтобы не раздувать микрокод).
