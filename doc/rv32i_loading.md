# Загрузка RV32I через IN

Решение: обычный `space` начинает со стандартного core. В одном потоке IN
идут установочные записи загрузчика, код и таблицы RV32I, заголовок гостевой
программы, её байты, затем входные данные программы. OUT содержит
гостевой вывод; `--report-status` добавляет завершающую запись.
`--core` для этого пути не нужен.

Стандартный core проверяет точное число прочитанных битов и отсутствие ошибки
через таблицу. Неполная запись выбирает слой ошибки, выдающий запись C/1
в OUT и очищающий PROCESSOR на следующем такте. Полная запись активируется
на следующем такте. Размер записи сохраняется: четыре инструкции и один
дополнительный байт: 37 байт при 2 МиБ, 44 байта при 64 МиБ.

Чтобы проверяющий код сам не оказался неполным, загрузчик устанавливается
записями по 48 бит при 2 МиБ и по 56 бит при 64 МиБ: данные лежат в неиспользуемых полях отключённого IN,
инструкция копирует их по постоянному адресу и возвращает стандартный core.
Нулевые участки не передаются: исходное пространство нулевое. Последняя
проверенная запись передаёт управление установленному загрузчику. Его первый
слой только переключает слои; IN начинает работу на следующем такте.

Загрузчик находится выше гостевой памяти, отдельно от загружаемого RV32I.
Он читает фиксированный диапазон от регистров до конца слоёв RV32I и проверяет
статус IN копированиями и LUT. Затем читает 12 байт заголовка: `RVS1`, длина
программы, entry (числа little-endian). Проверяет подпись, длину от 4 байт
до выбранного объёма гостевой памяти (по умолчанию 524288),
выравнивание entry и наличие целой инструкции по entry. Читает программу,
проверяет полноту и активирует первый слой RV32I; pc берётся из заголовка.
Ошибка этого загрузчика записывает причину 11 и очищает PROCESSOR.

Генератор и оболочка только создают/передают байты; проверки, загрузка и
выполнение инструкций гостевой программы происходят копированиями в space.
Генератор выводит ширины полей, установочную запись и размещение загрузчика
из --space-bytes. Число инструкций PROCESSOR остаётся 256; готовый пакет
должен исполняться эмулятором с тем же размером пространства.

## Запуск

Готовое задание pForth собирается вместе с Forth-текстом и запускается
напрямую из одного файла: [file_job.md](file_job.md).

```sh
make
python3 scripts/rv32i/build.py examples/rv32i/sum.c --stream -o tmp/sum.stream
printf '1 2\n' | python3 scripts/rv32i/run.py --stream tmp/sum.stream
```

Вывод `3` с переводом строки, код процесса 0. Для прямого запуска:

```sh
(cat tmp/sum.stream; printf '1 2\n') | build/bin/space
```

Оболочка запуска передаёт пакет, затем продолжает передавать живой stdin.
Для завершения этой программы не нужно закрывать stdin. `--in`, `--out`,
`--trace`, `--dump-space`, `--ticks` поддерживаются и в этом режиме.
Ошибка внешней передачи файла/потока даёт код оболочки 125; она не становится
ошибкой файлового канала пространства. Ошибки самого IN проверяет загрузчик.

Для сырой программы RV32I используется `modules/rv32i_stream.py` с
параметрами `--program PROGRAM --output PACKET --manifest MANIFEST`;
флаг `--io` включает профиль ECALL. Пакет подходит только к стандартному
core соответствующей конфигурации.

Причина 11 обозначает ошибку загрузки после установки загрузчика.
Обрыв установочной записи останавливает стандартный core раньше: STATUS
остаётся 0, OUT содержит запись C/1. С `--report-status` ошибки загрузчика
сообщаются записью L/11, завершение и исключения RV32I — записью R.
Подробности передачи содержатся в общем журнале каналов. Проверяется
полнота чтения, а не подлинность передаваемого кода: поток должен содержать
подготовленный для исполнения образ.

`make test-rv32i-c` включает 79 проверок нового пути, включая реальные
частичные чтения с ferror. Сырые IN/OUT, команды, дампы и журналы находятся
в `tmp/space-tests/rv32i-stream`. Общая регрессия — `make test`.

## Размер пространства

Обычная сборка сохраняет 2 МиБ. make bins-large создаёт space-64m из тех же
исходников эмулятора с пространством 64 МиБ. Адрес расширяется с 24 до
29 бит, инструкция — с 71 до 86 бит. Генераторы поддерживают размещения
от 2 до 256 МиБ, степенями двух; проверены обычное размещение и 64 МиБ.
Гостевая память ограничена четвертью пространства: до 512 КиБ или 16 МиБ
соответственно. Пример увеличенного размещения:

```sh
make bins-large
python3 scripts/rv32i/build.py examples/rv32i/sum.c --stream --space-bytes 67108864 --memory-bytes 16777216 -o tmp/sum-64m.stream
printf '1 2\n' | python3 scripts/rv32i/run.py --stream tmp/sum-64m.stream --space-bytes 67108864 --space build/bin/space-64m
```

Проверки полного диапазона и сохранения прежних пакетов описаны в
[расширении гостевой памяти](rv32i_memory.md). Достаточность 64 МиБ
для полного компилятора и Linux пока не доказана.

Измерения для C-примера `sum.c` (O2):

| Часть | Размер |
| --- | ---: |
| RV32I с вводом-выводом: состояние, таблицы и 111 слоёв | 268576 байт |
| Загрузчик: 19 слоёв | 43168 байт |
| Область констант, таблиц и слоёв загрузчика, с промежутками | 108704 байта |
| Установочные записи загрузчика, 2641 запись | 97717 байт |
| Машинная программа C | 1092 байта |
| Полный пакет IN, включая заголовок | 367397 байт (около 359 КиБ) |

Размер пакета не равен занятой памяти: установочные записи используются
повторно в одном буфере. Гостевая память по умолчанию занимает отдельные 512 КиБ.
Заголовок размещён по адресу 1966080 байт, поэтому текущий путь требует
пространство 2 МиБ даже при небольшом пакете. Установка занимает примерно
8000 тактов; формат по 48 бит выбран ради проверки каждой записи через
существующий четырёхинструкционный core. Эту цену установки можно позже
уменьшить другим проверяемым форматом core.

Практическая рекомендация: 2 МиБ достаточно для проверенных текущих
экспериментов; целевой размер следующей конфигурации — 64 МиБ. Это даёт
запас для нескольких модулей, более крупных программ и данных, но не
гарантию для любого неизвестного эксперимента. Само ядро пространства
проверено при 64 МиБ, 256 инструкциях, полях 28/29/29 бит; генератор RV32I
пока остаётся рассчитанным на 2 МиБ. Одновременно с переходом следует
параметризовать его формат, размещение и объём гостевой памяти.
